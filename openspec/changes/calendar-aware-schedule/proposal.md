# Proposal

## Why

当前计划只支持"按星期"的固定安排（每天／周一至周五／自选星期），完全不识别中国法定节假日与调休：国庆假期里"周一至周五"的习惯仍会被算作应做日（实际在放假），调休上班的周六反而不算（实际要上班）。用户要求支持"工作日／非工作日"两种安排，并"做好法定假期处理"——应做日、统计分母、回归判定都要随官方节假日安排正确调整。

## What Changes

- 计划新增可选字段 `dayType`：`'workday'`（实际工作日）｜`'restday'`（实际休息日）｜缺省 `null`（沿用按星期的 `weekdays`）。旧计划、旧备份、AI 草稿一律不受影响。
- 内置**年度节假日表**（随包发布；含法定节假日与调休上班日），提供唯一判定函数；未收录的年份安全回退为"周一至周五＝工作日"。
- 所有"今天有没有安排、哪些是应做日、7/28 天统计分母、连续错过回归、首次执行日、日程文案"统一改走同一个函数，保证口径一致。
- 编辑页提供 **工作日／非工作日** 快捷选项（替换原"周一至周五"；自选星期的"自定义"保留），摘要、提示文案随选择更新。
- 云端协议接受 `dayType`（`server/protocol.js` 与共享领域校验同步升级）；公开分享的轻计划可公开"工作日／非工作日"标签。
- 非目标：第三方节假日 API、云端下发日历、按城市／公司自定义日历、农历节气、更多日程类型。

## Capabilities

### New Capabilities

- `holiday-schedule`：工作日／非工作日计划与法定节假日、调休的忠实对齐。

### Modified Capabilities

无（主规范目录没有已归档能力；本变更作为独立增量）。

## Impact

- 客户端：`core/holidays.js`（新增，日历表＋判定）、`core/habits.js`（调度判定、校验、文案）、`services/plan-form.js`、`services/gentle-return.js`、`core/share-presentation.js`、`pages/edit`、`pages/detail`、`pages/manage`。
- 服务端：`server/protocol.js`（命令字段白名单）、`server/features.js`（分享快照投影）；经 `npm run build:cloud` 生成副本。
- **部署耦合**：旧版云端会拒绝带 `dayType` 的计划（INVALID_REQUEST），因此真实设备启用前必须部署 `jiancheng_daka_api`（与 `jiancheng_daka_features`，如涉及分享投影）——本地实施先行，部署单独授权、单独验收。
- 数据：**无迁移**。旧计划缺省 `dayType`，行为与现状完全一致；仅在用户保存时写入新字段。
- 测试：领域边界（节假日/调休/跨年/未知年份）、页面表单与摘要、服务端合同与分享投影、回归。
- 风险：年度日程每年由国务院办公厅公告发布——日历表需随版本更新；未更新年份走安全回退，不阻塞打卡。
