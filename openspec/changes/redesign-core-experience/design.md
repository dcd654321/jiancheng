# Design

## Context

现状：今日卡片显示"平时 X · 忙时 Y"与"今天按 X"两行相近信息；`completeMinimum`（按忙时目标打卡）已在 reducer、协议与同步队列实现并测试，但客户端开关 `completeMinimumEnabled` 未开启，快捷入口全部隐藏；回归卡"按原目标继续"跳转详情页，行为与文案不符；完成 toast 为"已保存到云端"；进度页日期区间为 ISO 格式，空数据仍渲染日历与图例。视觉体系集中在 `app.wxss`，页面级样式仅今日与助手两处。

## Decisions

任务卡改为两行结构：第一行名称＋「打卡」胶囊按钮，第二行"今天 X 单位"＋忙时青柠标签。青柠仅允许出现在忙时目标相关元素（标签、软按钮、部分完成日历格）。简化的"今天 X（原 Y）"只在 `simplified` 时出现，不再与"平时"重复。`detail` 模式只影响标题是否可点击，其余一致。

忙时一键打卡依赖既有 `completeMinimum` 能力与开关：启用开关属客户端配置变更；服务端已包含该命令与校验，但共享测试环境的部署与真实回执核验未完成，任务中单列且不得勾选。旧云兼容分支（`quickMinimumEnabled` 为假时显示两步"少做一点"流程）保留并继续有测试覆盖。

回归卡两个动作直接完成今天的记录：忙时按钮调用 `completeMinimum`，原目标按钮调用 `complete`。理由：回归时刻的核心诉求是"一步接上"，原实现跳详情页与文案不符；误触由始终可见的"撤销打卡"兜底。目标为 1 或无忙时目标时不显示对应按钮，退回"今天少做一点"输入。回归完成的 toast"接上了 · 已同步"同样只在云端确认后出现（沿用 `mutate` 时机与 `returnCompletion` 标记）。

文案与反馈：toast 不再说"已保存到云端"，改为"记下了 · 已同步／第一次，记下了 · 已同步／接上了 · 已同步"；"已同步"的显示条件与旧文案完全相同（云端确认后才显示），不放松诚实边界。数据层的"简化完成"用户可见文案统一为"忙时完成"，`core/habits.js` 的读屏描述同步为"忙时"。

进度建议为新纯规则模块 `core/progress-advice.js`：只使用区间内的 `planned／standard／minimum` 计数；计划日少于 3 天不输出；完整完成率 ≥70% 建议保持，完整完成率 <40% 且忙时占比 ≥30% 建议保持小目标，总记录率 <30% 建议缩小一档，其余输出中性句。文案标注"根据最近记录，不会自动调整你的目标"，不推断执行时段等无数据结论。

星期按钮保留现有 4+3 固定网格（`repeat(4)`），不采用原型稿的 7 列一行：320px 宽下 7 列单键约 35px，低于可接受的触控宽度；4+3 网格在窄屏可用且已有测试锁定。此为对原型稿的明确偏离，实施记录中注明。

## Verification and Rollback

自动测试覆盖：空状态与模板参数、任务卡新结构与旧云分支、忙时一键（`completeMinimum` 走既有引擎测试）、回归卡三种动作（原目标／忙时／退回输入）、toast 文案与时机、进度建议五种输入、日期短格式、术语断言更新。结构检查、云包一致性、OpenSpec 严格校验与原生编译单列。模拟器点击、云端回执核验与真机验收未完成前不计入通过。

回滚：独立提交到 dev，回退提交即恢复旧界面；`completeMinimumEnabled` 可单独改回关闭；无数据库迁移、无云函数变更。
