# Design

## Context

参见 `proposal.md`。当前领域模型有历史计划版本、按日任务和完成状态；客户端读取的是云端确认快照叠加本机待同步操作的当前账户视图。今日页已有同步告警和“简化／恢复／完成”操作，本批不改变其写入路径。

## Goals / Non-Goals

**Goals:** 用确定性的只读推导识别“今天可以回来做”的习惯，给一个轻量可执行入口；在离线或冲突时保持数据反馈诚实。

**Non-Goals:** 不保存漏做计数、不补签、不建提醒和自动任务、不改变计划版本或云端状态协议。

## Decisions

1. 新增客户端纯函数，以显式传入的当前账户状态和今天日期计算。只对今天待完成的习惯回看昨天起的日期，跳过非执行星期，遇到完成记录、首次生效前或暂停/归档版本即停止；达到两个未完成计划日就停止扫描。暂停/归档作为主动中断而非可跨越的“休息日”。备选方案是保存连续天数，但会增加迁移与多设备同步复杂度。
2. 今日页最多展示一个回归提示，选择当前待完成排序中的首个符合条件的习惯，避免最多五个并排提示。原目标保持现有默认数值，点击进入该习惯详情而不写记录；小目标复用现有可编辑确认弹窗，恢复原目标复用现有操作。备选方案是回归提示内直接完成，会造成误打卡。
3. 同步告警存在时不展示回归提示。当前账户的待同步队列虽会投影到本机视图，但远端冲突或不确定状态时停止评价过去记录更稳妥；待状态恢复后重新推导，不存一次性提示状态。
4. 完成回归任务沿用现有非阻断 Toast，给予短文案；待同步时明确提示。已有第一次完成反馈优先，避免同一次操作弹两条消息。

## Risks / Trade-offs

- [历史计划版本较多] → 只回看至满足两个未完成计划日或遇到中断；最多五个习惯，避免全量统计。
- [提示带来被责备感] → 使用事实性、非惩罚文案；不展示连续天数、失败率或补签入口。
- [当天跨日或其他设备刚更新] → 操作仍由既有日期/冲突校验约束；页面刷新时重新推导，状态不持久化。
- [未设置忙时值或目标为 1] → 保留现有手填能力；目标为 1 时隐藏无法成立的小目标操作。

## Migration Plan

只提交客户端页面、纯推导服务和测试到 `dev`，不修改 `server/`、云函数、集合、身份映射或正式环境配置。回滚此批独立提交即可恢复旧界面，不清理任何用户记录或待同步队列。真机及正式云验收继续单列，未验收不合并 `main`。
