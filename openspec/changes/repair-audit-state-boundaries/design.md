# Design

## Context

动机与范围见 proposal.md。活动客户端只有云端账户权威数据与会话内存草稿；features 会无条件写入配额文档，而核心 API 仅在清理与限流标志明确为 true 时执行对应删除清理。

## Goals / Non-Goals

**Goals:** 修复现有状态边界，保留合法确认数据并恢复正确只读状态；保证账户代次与业务日期隔离；使 features 与核心清理的前提一致。

**Non-Goals:** 不修改持久数据结构、认证来源、平台权限、云环境变量或部署状态；不扩大删除范围，不自动处理历史遗留云文档。

## Decisions

1. 回执确认与网络状态分开处理：离线仍接收合法 snapshot，但 phase 保持 offline、ready 为 false。有已确认数据时读回作为只读；联网后沿用现有 recoverConnection 核对。丢弃合法回执会导致不必要的重复重试。
2. 限流数据库文档名称保持现状；仅暖实例缓存用 owner/epoch 的组合键。全球拒绝不绑定账户。自动丢弃全球配额或重写限流数据均不在范围。
3. features 明确要求清理及限流配置为 true，与 API 现有实际清理条件一致。不让核心 API 在缺省配置时扩大物理删除，也不让 features 默认创建无法清理的文档。
4. 规则预览令牌存入由统一日期模块计算的业务日，consume 校验账户、日、期限并一次性删除；不把身份或输入放入 URL 或本机持久存储。
5. 编辑页面在提交前核对绑定的账户与业务日，不依赖周期刷新及时运行。会话草稿按版本接续，隐藏旧实例与旧回执无权覆盖或删除较新输入。
6. 表单刷新时读取当前创建容量，自动改为明天同时调整干净基线；已确认的同 id 创建走核对返回，不按新创建的容量拦截或再次写入。
7. 分享导航锁贯穿回执与页面切换，导航失败释放本次锁。仅修复已有页面合同，不开启公开分享门禁；短句开关、模板单位与加载卡片通过实际模拟器截图核验。

## Risks / Trade-offs

- 缺少两项配置的 features 在后续部署时会被关闭 → 部署前核对对应 API 和 features 的精确函数配置，单独取得授权并验证删除重建。
- 本地夹具不能证明线上清理或网络时序 → 自动回归与受控页面证据分开记录，真机双账户及实际部署留待后续验收。

## Migration Plan

本轮只修改 dev 工作区并生成云函数副本，不操作云端资源。后续部署前检查本项目专属函数与两项环境变量；不得改其他小程序或共用认证配置。回退只撤销本轮差异并重新生成，保留开始前已有修改；不执行 Git 整体 reset，不删除旧设备或云端文档。
