# Design

## Context

当前测试环境 `cloud1-d4gq76oyt363f08a7` 的活动入口是 `habitApi`；新服务端源码固定使用 `jiancheng_daka_accounts`。旧集合当前有 1 条账户文档，包含 1 个习惯及记录。新函数虽显示 Active，但远端代码与变量尚未核验。正式共享环境的 403 与本次同 AppID 测试云迁移无关。

## Goals / Non-Goals

**Goals:** 测试云完成有前缀的函数和集合切换，已有确认记录不丢失，旧客户端队列不会写入新集合；之后安全清理旧资源。

**Non-Goals:** 不触碰正式共享环境、共用认证、其他小程序、个人本机旧版备份或尚未验收的新功能。

## Decisions

1. 先保存旧集合数据的本机忽略备份及结构摘要；不得在新账户可读、可写且恢复前删除旧文档。备份不进 Git，不在日志显示账户 ID 或习惯内容。
2. 新集合先确认不存在再创建，客户端直读写须禁止。复制旧账户时保持 `_id` 与完整 payload，不重新推导身份、不修改 revision、epoch 或回执；如现有文档不能通过当前领域校验，停止迁移。
3. 现有新函数先核验当前版本/变量；覆盖前需可恢复的版本快照。仅设置本函数所需变量，不改旧 `habitApi` 或全环境配置。未能备份或验证时停止覆盖。
4. 客户端使用同测试环境的 `jiancheng_daka_api`，并给缓存、同意与待同步队列加入 `jiancheng_daka` 命名空间。旧队列不自动重放；如旧范围仍有待同步操作，暂停切换并先处置。
5. 切换后验证读回、创建/打卡、重启恢复与错误路径。清理旧函数和集合之前再次核实没有调用方、旧数据备份可读且新数据一致；失败时恢复旧客户端配置，保留两边数据，不自动把新写入覆盖旧库。

## Risks / Trade-offs

- 旧测试账户未同步操作可能尚在设备中：切换前读取队列摘要，不静默丢弃或跨命名空间重放。
- 直接复制账户可能与新版协议不兼容：先本地验证结构和新服务端读取，再写新库。
- 云端新函数 Active 不代表代码正确：部署前保存可恢复版本并受控验证。
- 删除旧集合不可逆：数据级备份、逐项比对和用户确认后才执行；若无法可靠验证则保留旧集合并明确未完成。

## Migration Plan

1. 审计测试环境、待同步队列和现有账户，保存备份及函数版本。
2. 创建并保护新集合，部署/配置新函数，先做不写库的入口与身份验证。
3. 迁移旧账户并核对，切换 dev 客户端，执行完整模拟器及双用户验证。
4. 达到清理门禁后删除旧测试函数和集合；保留恢复记录。只在用户另行确认后合并 main。
