# Prefixed Test Cloud

## Purpose

让本小程序的测试环境也使用专属前缀资源，在切换时保护已有测试账户和待同步操作。本规范为目标状态，不表示已完成远端部署。

## ADDED Requirements

### Requirement: 前缀测试资源

测试客户端 SHALL 在完成迁移验收后仅调用 `jiancheng_daka_api`，服务端仅使用 `jiancheng_daka_accounts`，不得失败后自动回退 `habitApi` 或 `yidian_accounts`。

#### Scenario: 迁移完成后打卡
- **WHEN** 用户在测试环境创建习惯并打卡
- **THEN** 请求只到前缀函数与集合，重新进入仍可读到确认记录

### Requirement: 已有记录与队列保护

系统 MUST 在删除旧测试资源前保存可恢复记录并核验新账户完整；旧缓存和待同步队列不得自动写入新集合。

#### Scenario: 旧账户已有确认数据
- **WHEN** 旧集合存在账户和记录
- **THEN** 迁移保留其身份键、代际、版本与业务内容，校验失败时不切换或删除旧资源

#### Scenario: 旧设备还有待同步操作
- **WHEN** 旧作用域中存在未确认操作
- **THEN** 停止自动迁移，提示先处理，不跨作用域重放或静默丢弃

### Requirement: 安全清理旧资源

系统 SHALL 仅在新资源已可读写且旧资源不再被调用后清理旧测试函数和集合；清理不影响共享正式环境与其他小程序。

#### Scenario: 新函数未验收
- **WHEN** 新函数版本、权限或真实业务流程未通过
- **THEN** 保留旧函数和集合，报告阻塞，不执行不可恢复的删除
