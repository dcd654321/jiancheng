# Proposal

## Why

渐成已具备双档目标和基本首次引导，但本轮页面审查发现恢复入口不一致、操作含义与完成反馈仍需明确；用户也明确要求保留墨绿、浅底和青柠忙时标识，并降低色彩刺激，提供两个可切换主题。本变更把这些要求整理成可独立实施、逐项验收的增量方案，服务于“理解用途—创建—记录—修改—再次进入”的核心任务。

## What Changes

- 保留“今日／进度／我的”及既有双档目标规则，统一失败恢复入口，明确记录动作，保留当次访问的完成反馈及撤销入口。
- 模板创建使用紧凑确认页；自定义和编辑保留完整表单。合并回归提示中的重复操作，删除与模板重复的助手页面入口，进展文案只解释真实记录。
- 提供共享布局的“薄雾绿 mist”和“暖纸白 paper”，默认薄雾绿；采用浅底、低饱和边框按钮和局部忙时色块，落实字号、触区和状态规范。
- 新增主题选择页、会话预览及云端偏好协议。复用偏好集合，使用独立主题动作和开关，保留身份、幂等、冲突、删除与账户隔离约束，不连带启用分享或提醒。
- 交付逐页执行规格、需求—文件—验收映射、确定性测试夹具及实施顺序。2026-09-30已实施主体；2026-10-01按复核R1–R7修复预览、会话清理、等待反馈及操作可达性。
- 2026-10-01产品审查后，用户授权继续本地优化：今日摘要减量、模板目标解释、两档记录文字精简、已有习惯统计前置以及明日计划入口文案。只重排现有事实与入口，不增加统计算法、默认值迁移或云动作。
- 2026-10-01用户报告完成反馈常驻并授权一起修复同类问题：反馈仅展示最新确认项，5秒后收起，撤销后不回退展示旧项；旧访问的写入、保存、恢复和确认弹窗回调不得弹提示、跳转或提交失效意图。
- 2026-10-01按用户要求重新通查逻辑：补齐失效编辑与首次就绪绑定、已确认创建重试校验、首次执行日期、主题及置顶偏好版本单调、重入回调与跨日反馈隔离。服务端修复事务原地修改未持久化的清理标记，并让提醒收件人与现有受信调用方身份保持一致；只修改本项目源码和生成副本，不部署、不迁移、不启用提醒、不调整权限。

## Capabilities

### New Capabilities

- `journey-refinement`：核心旅程增量优化、可恢复反馈、紧凑创建及可读可操作的页面状态。
- `appearance-themes`：双浅色主题、云端主题偏好、独立能力开关及预览与保存行为。

### Modified Capabilities

无。当前主规范目录没有已归档能力；旧变更 `redesign-core-experience` 仍为进行中，本变更作为后续增量，不重置其任务、不沿用其测试结论。对于完成反馈、主题与紧凑确认等新增行为，以本变更及本次交接文档为准；旧变更中的已完成实现仍须保留并回归验证。

## Impact

- 客户端：共享 WXSS、task 模板、today/edit/progress/mine/detail 等页面、共享生命周期与恢复处理；现有 appearance 页面、主题服务、主题独立配置。
- 服务端：`server/features.js`、`server/entries/features.js` 的主题读写动作与入口能力隔离；`server/cloudbase-repository.js` 的事务变更比较、`server/identity.js` 与 `server/reminders.js` 的受信调用方复用；通过构建脚本生成云副本。复用既有渐成集合，不新增集合、不批量迁移。
- 测试：领域约束、页面/会话、偏好协议及入口开关自动测试；双主题截图、微信工具、真机与双账户验证分别记录。
- 风险：异步回执错用账户、主题加载闪烁、共享偏好版本冲突、未知结果重复提交，以及生成副本与实际部署不一致；设计及验收文件提供对应约束。
- 非目标：计时器、自动累计、更多活跃习惯名额、积分、排行榜、强制登录引导、订阅弹窗、暗色主题、系统跟随、离线写入及自动部署。
- 交接入口：`docs/AI-OPTIMIZATION-HANDOFF-20260930.md`；验收入口：`docs/AI-OPTIMIZATION-ACCEPTANCE-20260930.md`。本轮获用户授权修复逻辑与回归测试；不写真实云端、不部署、不提交或合并。
