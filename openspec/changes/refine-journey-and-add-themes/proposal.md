# Proposal

## Why

渐成已具备双档目标和基本首次引导，但本轮页面审查发现恢复入口不一致、操作含义与完成反馈仍需明确；用户也明确要求保留墨绿、浅底和青柠忙时标识，并降低色彩刺激，提供两个可切换主题。本变更把这些要求整理成可独立实施、逐项验收的增量方案，服务于“理解用途—创建—记录—修改—再次进入”的核心任务。

## What Changes

- 保留“今日／进度／我的”及既有双档目标规则，统一失败恢复入口，明确记录动作，保留当次访问的完成反馈及撤销入口。
- 模板创建使用紧凑确认页；自定义和编辑保留完整表单。合并回归提示中的重复操作，简化助手主入口，进展文案只解释真实记录。
- 提供共享布局的“薄雾绿 mist”和“暖纸白 paper”，默认薄雾绿；采用浅底、低饱和边框按钮和局部忙时色块，落实字号、触区和状态规范。
- 新增主题选择页、会话预览及云端偏好协议。复用偏好集合，使用独立主题动作和开关，保留身份、幂等、冲突、删除与账户隔离约束，不连带启用分享或提醒。
- 交付逐页执行规格、需求—文件—验收映射、确定性测试夹具及实施顺序。此次只产出提案与文档，全部实施任务保持未完成。

## Capabilities

### New Capabilities

- `journey-refinement`：核心旅程增量优化、可恢复反馈、紧凑创建及可读可操作的页面状态。
- `appearance-themes`：双浅色主题、云端主题偏好、独立能力开关及预览与保存行为。

### Modified Capabilities

无。当前主规范目录没有已归档能力；旧变更 `redesign-core-experience` 仍为进行中，本变更作为后续增量，不重置其任务、不沿用其测试结论。对于完成反馈、主题与紧凑确认等新增行为，以本变更及本次交接文档为准；旧变更中的已完成实现仍须保留并回归验证。

## Impact

- 客户端：共享 WXSS、task 模板、today/edit/progress/mine/assistant 等页面、共享生命周期与恢复处理；拟新增 appearance 页面、主题服务、主题独立配置。
- 服务端：`server/features.js`、`server/entries/features.js` 的主题读写动作与入口能力隔离；通过构建脚本生成云副本。复用 `jiancheng_daka_preferences`，不新增集合、不批量迁移。
- 测试：领域约束、页面/会话、偏好协议及入口开关自动测试；双主题截图、微信工具、真机与双账户验证分别记录。
- 风险：异步回执错用账户、主题加载闪烁、共享偏好版本冲突、未知结果重复提交，以及生成副本与实际部署不一致；设计及验收文件提供对应约束。
- 非目标：计时器、自动累计、更多活跃习惯名额、积分、排行榜、强制登录引导、订阅弹窗、暗色主题、系统跟随、离线写入及自动部署。
- 交接入口：`docs/AI-OPTIMIZATION-HANDOFF-20260930.md`；验收入口：`docs/AI-OPTIMIZATION-ACCEPTANCE-20260930.md`。本次不修改业务代码、不写云端、不部署、不提交或合并。
