# Design

## Context

动机见[proposal](proposal.md)。运行证据在[本轮证据索引](../../../docs/audits/2026-09-30-journey-review/EVIDENCE.md)；逐页、token、合同细节在[AI执行规格](../../../docs/AI-OPTIMIZATION-HANDOFF-20260930.md)，验证步骤在[验收清单](../../../docs/AI-OPTIMIZATION-ACCEPTANCE-20260930.md)。这些文件共同组成实施输入，不能只按生成图片重写页面。

已核对的当前实现：

- `today` 的近期完成仅一个对象、约6秒，到onHide清空；`ui.mutate` 使用页面串行锁；`cloud-session` 保存内存pendingEvent并用相同请求重放恢复。当前undo只改状态，不恢复当天目标。
- edit共用领域校验，模板/助手/分享已有不同入口；一次性草稿与编辑版本不能因重渲染再消费。创建容量为5，编辑按次日生效。
- `features-client` 与云入口依赖features总开关；当前偏好协议无theme，原setPreferences只允许pin/reminder字段；偏好文档已有共享revision、事务和幂等收据。
- features、分享、提醒能力有独立安全前提，默认未全面开启；当前工作区已含上一轮UI改动。本变更不回退或重新勾选旧变更任务。
- 根AGENTS禁止本机账户持久状态；OpenSpec背景中“本地缓存与离线队列”属过时描述，不作为本次设计依据。

## Goals / Non-Goals

**Goals:**

- 最大限度复用现有领域命令、页面路由与会话恢复，修改用户可见信息及状态组织。
- 共享结构和语义token实现两个主题，云偏好可独立启用、失效和回滚。
- 每个需求对应可复现验收，不把静态稿、注入渲染、自动测试及云端/真机证据混为一类。

**Non-Goals:**

- 不新增离线队列、计时、习惯名额、统计算法、自动调整目标或新的认证路径。
- 不更换导航架构、不复制两套业务页面、不新增设置中间页。
- 不在本次规划阶段改业务代码、生成云副本、写云端、部署、迁移、提交或合并。

## Decisions

### D1：在共享生命周期内收敛恢复

提取today现有读取重试到共享UI层，页面消费一致loading/unavailable/retrying状态。复用withLifecycle的可见性、版本和日期机制；防重复请求，检查context与页面是否仍有效。公开分享页用原公开读取器，不要求私有账户就绪。

未知写入复用现有session.retry/recoverConnection；禁止重新dispatch产生新的operationId。把“先核对”解释为同请求幂等恢复，无需另建operation查询接口。原网络恢复防抖与单次触发保持。

替代方案：每页各写重试容易产生生命周期分叉；新增全局轮询增加请求并不能解决幂等问题，均不采用。对应UX-01 / A01–A06。

### D2：edit内分两种呈现，不拆创建协议

模板和有效草稿走紧凑确认，自定义/编辑走完整表单；字段和验证复用plan-form及domain。频率默认收起但摘要可见，开始日始终可见；键盘关闭时固定提交区，打开时回到内容流，预留真实安全区。

保留_id、baseRevision、startDate及一次性草稿上下文。主题/恢复只重绘，不重新onLoad或构造创建命令。容量冲突不能自动切日期。

替代方案：新增确认页会使字段副本、返回修改及草稿所有权更复杂；删除频率设置损失控制，因此不采用。对应UX-03 / A11–A17。

### D3：临时展示多条完成反馈，数据仍来自云端

用仅当前可见访问有效的集合替代单_recentDone定时器；每项含habitId、业务日期和完成前顺序，数量最多5。每次权威状态更新派生行：本次完成项原位保留，其他既有完成项进入完成分组并去重。计数不从展示集合推算。

onHide/onUnload、账户context或日期变化清集合。旧日期回执按原请求校验处理，不能加入新日期展示。保留写串行锁，仅增强按钮loading和结果文案。undo成功按既有领域结果呈现，忙时目标2不自动改5，另有恢复原目标命令。

替代方案：无限保留跨会话卡片需持久UI状态且干扰新一天；单纯延长Toast仍不便回看，均不采用。对应UX-04/05 / A18–A26。

### D4：单一组件结构、双套语义颜色

使用page/surface/ink/secondary/primary/busy/soft/border/error等token，所有页面与自绘状态一致消费。默认mist，paper只换颜色；系统无衬线字、44px触区与48px推荐按钮。忙时色限小标签，日常记录用描边，提交才用低饱和实心。

基础库支持检查在实施时记录：若WXSS变量在目标渲染链路不可靠，从同一token源生成主题作用域样式，业务WXML不复制。原生导航/Tab使用官方能力并验证图标素材；系统键盘/授权弹窗不纳入换肤承诺。

替代方案：两个独立UI方向会改变布局和肌肉记忆；整体透明度降低会损害对比度，因此不采用。对应UX-02/TH-01 / A07–A10、A27–A30。

### D5：同函数、同偏好集合，独立主题动作与开关

新增appearance配置/客户端与主题页面，客户端默认关闭。云端在features入口识别白名单getAppearance/setAppearance，使用独立HABIT_APPEARANCE_ENABLED；身份、清理、限流、平台来源/AppID条件仍必须满足。旧features/reminder动作继续按原开关限制，不被新开关放开。

新增theme可选字段，合法枚举mist/paper；缺失读取mist、不写库、不迁移，非法值报告PREFERENCES_CORRUPT。主题成功投影仅revision/theme（写入可含replayed），不返回整份偏好。共享revision和preferenceReceipts，先幂等核验再版本比较；主题写只改允许字段，原偏好写保留theme。重放返回当前视图，与现有偏好幂等语义一致。

替代方案：打开features总开关风险不必要；扩展原patch强耦合门控；独立新云函数/集合增加资源管理，因此选择原函数内独立动作。对应TH-02 / A31–A42。

### D6：账户会话级保存协调、页面级预览

页面只持previewTheme；appearance客户端持当前context、已确认theme/revision、在途读取和最多一个冻结保存请求。保存成功校验context后广播主题，不重建页面。离页只取消预览；已发事务仍由协调器接收回执，未知结果可重入核对。

网络或服务结果不明保留冻结payload，只允许原ID重放；单纯读取颜色不能证明旧请求已经结束。明确冲突先读云端，保留预览，用户再次确认才新建操作。上下文/epoch变化清理内存并丢弃旧回包。冷启动不恢复本机请求，仅重新读当前云值。

外观读取不加入阻塞核心启动的dataReady链；默认浅底先可用，偏好读取去重，不定时轮询。无合法revision/离线/主会话pending或conflict时禁止主题保存。

替代方案：本机持久化能减少闪烁但违反项目数据约束；保存前全局乐观换肤会让失败像已成功；关闭页面即“取消事务”与云端事实不符，均不采用。对应TH-02 / A27–A29、A34–A38。

### D7：辅助说明减量，算法不扩展

助手主预览收敛到名称、两档、执行日和一句理由；细节折叠，采用仍进入确认。回归提示合并重复动作，gentle-return条件保持。progress-advice仅改事实与条件措辞，阈值、分母、日期与历史保持。分享直达补解释/出口但不启用关闭的能力。

替代方案：新增打卡奖励、召回消息、智能自动改目标不能解决当前理解与操作问题且增加维护，不采用。对应UX-06/07/08 / A43–A50。

## Risks / Trade-offs

- [样式变量/原生API支持未核验] → 记录目标基础库、微信工具与真机验证；不支持时保持中性可读原生区域，token采用单源生成作用域样式。
- [主题读取延迟出现一次配色变化] → 默认浅底、无动画、读取去重；不以本机账户缓存或阻塞核心页面换取无闪烁。
- [共享偏好revision导致跨设备冲突] → 明确冲突提示、读最新再由用户确认；不自动覆盖。
- [离页后的写入仍可能成功] → 保存协调器和明确待核对状态；不承诺取消已发事务。
- [多完成反馈重复计数/跨天泄漏] → 派生显示去重、最多5项、统计只用领域状态、测试午夜和context变化。
- [本地模拟被误认为云已通过] → L/W/D/C/U逐层报告，所有实施任务初始未勾选；受阻就记录BLOCKED。
- [共享生成副本扩散] → 从server源修改并build，核对各副本来源，部署目标需单独审查授权。

## Migration Plan

1. 当前仅整理提案，保留所有已有代码修改与旧任务证据。后续收到实施指令后，按tasks完成本地代码与测试，开关默认false。
2. 不批量迁移偏好：theme缺省mist，读路径无写，用户保存才新增字段；不碰其他小程序资源或共用认证。
3. 运行构建及常规/规范检查，确认SDK锁定依赖和合同测试实际执行；微信工具、真机、双账户另附证据。
4. 云端集成前列清环境、函数、代码/配置差异、开关、安全前提和恢复边界，取得适用授权。共享模块生成差异不等于允许部署全部函数。
5. 回滚先关闭主题入口与独立能力，核心默认外观继续可用；保留theme和历史，不清空账户。回退旧服务前检查字段与收据兼容；不能确认时保留新版服务并关闭新动作。
6. 用户测试确认后才安排独立发布/合并授权。规范文件齐全不代表实施完成、部署完成或生产就绪。
