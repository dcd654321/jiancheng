# Spec Delta

## Purpose

将已确认的融合视觉方案落地到微信原生小程序，在今日、进度、添加编辑、详情和我的页面保持统一的双主题与操作层级，同时保留现有云端确认、统计、照片约束和恢复能力，并提供可核验的视觉对照证据。

## ADDED Requirements

### Requirement: 固定视觉与双主题
系统 SHALL 使用冻结融合稿作为还原基准，薄雾绿主色 #246446、正文 #18382c、薄荷面 #edf6ef；暖纸白共享布局。标题24px、正文15px、任务名16px，主操作最小44px。关键正文几何误差 MUST 控制在2个逻辑像素以内，平台字形与原生导航和底栏差异单列记录。

#### Scenario: 相同数据的原生对照
- **WHEN** 在390px逻辑宽度以相同数据和状态显示五个核心页面
- **THEN** 输出冻结原型与原生截图并排图、关键尺寸和差异清单，未达标项不得标为通过

#### Scenario: 主题与窄屏
- **WHEN** 用户在两套主题、320至430px宽度或大字号下使用页面
- **THEN** 信息可读、内容不横向溢出，长名称按内容增高，关键操作保留44px热区

### Requirement: 今日时间线
系统 SHALL 将置顶任务独立放在时间线之前，其余按时间和稳定标识排序，无时间任务置后；完成项默认展开且可收起。常规完成行约68px、待做行约102px，操作列104px，窄屏100px，正文允许增高。

#### Scenario: 混合状态与收起
- **WHEN** 今日含已完成、待做、置顶及未安排时间的任务
- **THEN** 完成任务保留在对应时间位置，收起完成项只隐藏对应行，摘要继续使用全部真实任务

### Requirement: 详情复用可信打卡流程
系统 SHALL 在详情支持平时打卡、忙时打卡、撤销、只调整今天和恢复原目标，使用与今日一致的照片约束、上传、云确认和未知结果恢复；不得乐观写入完成状态。

#### Scenario: 照片约束与失败
- **WHEN** 必须照片的习惯在详情发起打卡，或服务端返回 PHOTO_REQUIRED
- **THEN** 打开共用照片流程；上传失败可重试，未知提交保留待核对内容，云端确认后才显示完成

#### Scenario: 上下文变化
- **WHEN** 上传或目标调整期间账户、日期或页面版本变化
- **THEN** 旧响应不得修改当前页面或向新账户提交旧操作

### Requirement: 既有业务边界保持
系统 MUST 保留容量、字段校验、草稿恢复、明天生效、真实7天与滚动30天及月历、监督、提醒、分享、公开入口及危险确认；不得引入原型内存保存和示例业务数据。

#### Scenario: 计划保存和读回
- **WHEN** 用户编辑计划并保存成功后重新进入页面
- **THEN** 显示云端确认的明天生效计划，失败保留可恢复输入，今日原计划保持原有规则

#### Scenario: 验证记录
- **WHEN** 完成实施与交付
- **THEN** 自动测试、源码、云生成一致性、OpenSpec、原生编译和模拟器分别记录；真实云、真机、双账户及用户UI验收只在获得对应证据后标记完成
