# Tasks

## 1. 接入前核对

- [ ] 1.1 在 dev 复核当前客户端云配置、传输层、服务端身份边界和现有测试，记录与 proposal/design 的差异；以代码位置和测试清单作为完成证据。
- [ ] 1.2 查验当前微信云开发共享环境的官方身份上下文语义，并用获授权的受控调用确认资源方、使用方及用户身份的映射；记录脱敏证据。无法确认时停止身份适配。
- [ ] 1.3 在任何远端改动前复核正式环境、本项目函数、集合、变量、权限及共享关系的实时状态，限定准确目标并保存可恢复的本项目配置；发现涉及共用资源时暂停并列出影响。

## 2. 客户端共享访问

- [ ] 2.1 增加显式的共享云实例配置与单次异步初始化；覆盖配置缺失、未授权、并发初始化、网络失败后重试及禁止回退旧测试环境的测试。
- [ ] 2.2 让本项目业务请求仅通过已初始化的目标实例调用专属函数；运行传输层测试，核对失败时不会显示可编辑的虚假空账户或同步成功。
- [ ] 2.3 为正式环境建立独立缓存与队列范围，保留旧测试快照和待同步操作；以带旧缓存首次进入正式环境、离线恢复、冲突测试确认没有跨环境重放。

## 3. 服务端身份和持久化

- [ ] 3.1 按 1.2 核实的可信上下文实现来源小程序和用户身份适配，拒绝缺失、非法或不匹配的身份；测试伪造 event 字段与未获准来源均不能创建账户或写入。
- [ ] 3.2 核对本项目集合、账户隔离、事务、幂等回执与版本冲突处理；用双用户、重试确认丢失和多设备冲突测试验证记录独立、单次生效及本地意图保留。
- [ ] 3.3 检查错误响应和诊断记录，确保不暴露密钥、原始用户身份或用户备注；运行对应错误路径测试。

## 4. 本地验证与受控启用

- [ ] 4.1 运行 `npm test`、`npm run check`、`npm run check:cloud` 和 OpenSpec 严格校验，记录命令、版本、结果及已有失败；确认生成的云函数副本与源代码一致。
- [ ] 4.2 在取得对应远端授权后，仅部署本项目专属函数和配置；核对部署前后版本、目标环境、变量与访问规则，不修改其他小程序资源或共用认证配置。
- [ ] 4.3 使用获授权的测试账户在正式环境验证首次创建、打卡、重进恢复、离线重试、双用户隔离和非法来源拒绝；保存脱敏结果，区分 SDK 调用、真机与单元测试证据。
- [ ] 4.4 远端验证通过后才在 dev 切换客户端活动目标；再执行一次完整回归并记录切换前后的配置与可执行回退步骤。
- [ ] 4.5 由用户在真机验收核心流程、失败提示及正式数据恢复；逐项记录通过/失败。仅在用户明确要求后另行合并到 main。
