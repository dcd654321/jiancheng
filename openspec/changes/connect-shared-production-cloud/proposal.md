# Proposal

## Why

小程序活动配置仍使用旧测试环境与旧函数，共享正式环境的调用方式、可信来源身份和启用配置尚未接通。需要一次边界明确且可验证的接入变更，让“函数已部署”最终成为用户可正常使用的数据服务。

## What Changes

- 为本项目增加共享环境调用与初始化失败处理，不悄悄回退到旧测试环境。
- 根据可信平台来源识别本小程序及用户，继续隔离账户、集合与离线队列。
- 经授权核验并配置本项目新函数和集合，再切换活动配置；保留旧测试数据及独立恢复路径。
- 建立创建习惯、打卡、重新进入、离线恢复、双账户隔离的验收记录。
- 非目标：不新增 AI 功能、不重设计页面、不自动迁移旧数据，不修改其他小程序及共用认证函数，不删除任何资源。

## Capabilities

### New Capabilities

- `shared-production-cloud`：共享正式环境中可验证、身份隔离、失败可恢复的习惯数据访问。

### Modified Capabilities

无。当前 OpenSpec 主规范为空；本变更仅新增共享接入能力，不将现有业务能力重新声明为新实现。

## Impact

- 拟修改：`miniprogram/config/cloud*.js`、`miniprogram/services/cloud-transport.js`、必要的会话配置传递、`server/handler.js`、云函数入口及对应测试；生成副本通过构建更新。
- 远端范围仅本项目 `jiancheng_daka_api` 与 `jiancheng_daka_accounts`；本提案不授予远端变更权限。
- 本地代码现状已核验。2026-09-22历史检查记录显示 product 已共享、新函数已部署、集合存在，旧正式函数已删除；远端状态会变化，实施前必须重新核验，不视为本轮实时验收。
- 验收成功标准：授权用户完成创建与打卡、重启恢复、离线重试不重复写入、不同用户互不可见，旧测试数据和其他小程序保持不变。提案完成不等于上述标准已经达成。
