# Shared Production Cloud

## Purpose

让渐成习惯打卡在获授权的共享正式环境中提供可靠的习惯记录服务，确保只有本小程序的合法用户能访问自己的记录，同时保留离线恢复能力、旧环境数据与其他小程序资源的独立性。本文件描述拟实现行为，不表示已经部署或验收。

## ADDED Requirements

### Requirement: 明确的正式环境访问

系统 SHALL 仅在用户同意数据说明且目标配置有效时访问指定共享正式环境；初始化未完成或失败时不得发起业务请求，也不得自动回退到旧测试环境。

#### Scenario: 同意后成功初始化
- **WHEN** 用户同意数据说明且共享环境初始化成功
- **THEN** 业务请求访问指定正式环境和本项目专属函数，不访问旧测试函数

#### Scenario: 缺少配置或未授权
- **WHEN** 配置不完整、用户未同意数据说明，或共享授权未通过
- **THEN** 不执行数据写入，不呈现可编辑的虚假空账户，并提供对应状态说明

#### Scenario: 网络失败后重试
- **WHEN** 初始化因网络失败且用户在网络恢复后重试
- **THEN** 系统能重新初始化，保留现有缓存和队列，并避免并发重复初始化

### Requirement: 来源与账户隔离

服务端 MUST 从受信平台上下文验证获准来源小程序及对应用户，拒绝身份缺失、非法或不匹配的请求；客户端提供的身份字段不得授予访问权。

#### Scenario: 两个用户独立使用
- **WHEN** 本小程序用户甲、乙分别创建并读取习惯
- **THEN** 各自只能读写自己的记录，即使伪造他人的账户字段也不能越权

#### Scenario: 其他来源或伪造身份
- **WHEN** 请求来自未获准的小程序，或可信上下文缺失但请求体含伪造身份
- **THEN** 服务端拒绝访问，且不创建账户或修改记录

### Requirement: 正式数据与旧数据分离

系统 SHALL 使用本项目专属数据集合及独立的正式环境缓存范围，不自动读取、上传、覆盖或删除旧测试账户、缓存与待同步队列。

#### Scenario: 带旧缓存首次进入正式环境
- **WHEN** 设备保留旧测试快照和未同步操作，随后首次进入正式环境
- **THEN** 系统使用新的正式账户绑定与缓存范围，旧数据保持不变且不自动上传

### Requirement: 持久记录与安全恢复

系统 SHALL 在正式云端确认后报告持久化成功，重新进入可恢复已确认记录；离线操作恢复提交时保持幂等和冲突保护。

#### Scenario: 打卡后重新进入
- **WHEN** 用户创建习惯并打卡，收到云端确认后重新进入小程序
- **THEN** 已确认习惯和记录仍可读取，不依赖旧测试环境

#### Scenario: 离线重试与确认丢失
- **WHEN** 当日打卡进入离线队列，恢复网络后同一操作被重试
- **THEN** 只产生一次业务效果，确认前不丢弃待同步操作

#### Scenario: 多设备冲突
- **WHEN** 本机待同步操作的版本与云端版本冲突
- **THEN** 停止自动覆盖并保留本机意图，等待用户明确处理

### Requirement: 受控启用与资源边界

正式服务 MUST 在身份访问约束与本项目配置均核验完成后启用；失败响应不得暴露原始身份、备注或密钥，接入过程不得修改其他小程序资源。

#### Scenario: 启用条件不满足
- **WHEN** 本项目服务启用配置缺失或访问约束未通过核验
- **THEN** 不切换客户端到可写的正式服务，用户不会收到虚假的同步成功提示

#### Scenario: 共用配置阻止接入
- **WHEN** 接通服务需要修改其他小程序也依赖的共用配置
- **THEN** 本次接入停止在该边界，报告影响并等待额外授权，不自动修改共用资源
