# Design

## 数据与命令

新增 `completeMinimum {type,id,date}`，不接受客户端传入目标值。reducer 从当天有效计划版本读取 `minimum`，要求当天有安排、目标合法、记录尚未完成且未手动调小，再将 `todayTarget` 设为 `minimum`、`status` 设为 `minimum`。沿用现有记录键、版本修订、日期边界、队列、操作号和服务端回执，不改变 `schemaVersion`。

如果今天已手动调小，继续使用原有“打卡”完成当前目标；快捷入口不出现，服务端也拒绝旧按钮请求覆盖自定义值。跨日和已完成请求同样拒绝。一次点击只处理一个习惯，其他记录保持不变。

## 今日页

进度区域同时标示“待做 N · 已做 M”。未完成任务显示今天当前目标；有预设忙时目标且未手动调小才显示快捷按钮。为避免多任务列表堆满操作，预设目标的自定义调整放在详情页；未预设目标时今日卡片仍保留“今天少做一点”。按钮文字含“打卡”，明确是对已做行动的声明，不把减量建议误当自动完成。已完成仍折叠且可撤销。按钮可点击区域维持至少 44px。

## 反馈

“我的”保留微信原生 `open-type="feedback"`，改为“意见与问题反馈”。本变更只验证入口结构；真机能否提交、后台能否收到需独立实测。

## 风险与回滚

本批不建立远程资源。客户端和服务器必须同时认识新命令；未上传新版云函数前客户端快捷操作可能被拒绝，因此不能把本地测试宣称为正式环境可用。回滚至本批前 dev 提交即可恢复旧入口；已有 `minimum` 记录仍符合旧数据结构。
