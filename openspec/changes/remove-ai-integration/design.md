# Design

## Context

动机见 proposal.md。当前 `createPlanAssistant` 同时管理规则方案、收费模型请求与会话草稿；页面通过客户端配置展示 AI 入口。模型适配器固定请求 DeepSeek，结果先映射为目录文案。账户删除独立清理 AI 请求和限流记录。仓库包含尚未提交的产品与表单优化，开始时 dev 与 origin/dev 一致，基线测试 427/427 通过。

## Goals / Non-Goals

**Goals:** 活动代码只提供确定性的规则方案；保留确认保存、账户上下文、跨日和会话草稿约束；旧 plan 包成为无依赖停用入口。

**Non-Goals:** 不修改主云配置、受信身份、集合权限、历史数据结构或其他应用；不部署、写云环境变量、删除云资源、归档、提交或合并。

## Decisions

1. 将规则草稿校验迁入 `core/plan-assistant.js` 并导出 `validateDraft`，删除 `ai-contract.js`、`ai-catalog.js`。`services/plan-assistant.js` 仅暴露 `rules/handoff/consume`，采用 `createPlanAssistant(options={})` 接口，保留有界、10分钟、一次性和账户上下文校验。应用装配不再注入云配置和 AI 配置。选择删除真实集成而非仅关闭开关，避免旧配置重新开启功能。
2. 保留助手路由与规则预览；入口改“小目标助手”，去掉 AI 状态、同意、隐私折叠和生成按钮。规则可离线预览，采用及保存仍沿用主云账户可写约束、容量检查与统一读取恢复；编辑页只消费 rule 草稿。
3. 删除 `server/ai-provider.js` 和 `server/ai-plan.js`。`server/entries/plan.js` 无依赖固定返回停用回执，旧资源名保留给未来经授权的停用部署。相比删除云函数，停用回执可为已安装旧客户端提供明确反馈。
4. 构建 plan 包仅生成入口及无运行依赖的 package/lock，按明确白名单清理旧生成 lib/shared 文件；`--check` 拒绝已知旧生成文件残留，未知用户文件和已安装 SDK 缓存保留。其他业务函数的 wx-server-sdk 锁定依赖不变。
5. 保留历史 AI 私有集合、owner/epoch 清理与相关开关，并用植入旧记录的 SDK 合同测试验证删除隔离。隐私说明移除新的 AI 发送说明；数据删除仍清理已有历史功能记录。

## Risks / Trade-offs

- [旧发布版本/线上旧函数仍可能运行] → 本次本地源码修改与线上停用分别记账；如需停用线上，精确列出目标云环境和 `jiancheng_daka_plan` 后取得部署授权。
- [构建时旧文件残留] → 删除确切旧生成文件，使用独立构建 fixture 检查旧模型模块消失和未知文件保留，不递归清理用户目录。
- [关闭功能后遗漏个人数据清理] → 保留历史旁路清理代码、集合权限与 SDK 隔离测试，不清空集合或撤销清理配置。
- [既有用户修改被覆盖] → 保存修改前差异，只增量编辑相关文件，最终检查差异与原有产品功能测试。

## Migration Plan

本地依次移除前端及生成实现、更新说明、运行 build:cloud 和必要验证。没有数据迁移。未来经授权部署时，仅用本变更的无依赖 plan 停用包替换对应环境中的同名函数，并上传纯规则客户端；验证旧请求无调用、预算与账单变化另行记录。回滚需恢复本次明确文件差异并重建产物，云端回滚独立审批，不能直接重开旧模型服务。
