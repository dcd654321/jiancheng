# Spec Delta

## Purpose

允许用户在习惯详情中明确确认后删除自己的一个习惯及其全部私人记录，同时保护其他习惯、账户设置和其他账户的数据。该能力规定不可恢复提示、云端确认、并发冲突与结果未知处理，使用户能判断删除是否已经完成。

## ADDED Requirements

### Requirement: 单项删除入口与明确确认

系统 SHALL 在有效习惯详情的“更多操作”内、归档下方显示红色“删除习惯”，并支持进行中、已暂停、已归档和尚未开始的习惯。执行前 MUST 明确展示目标名称、全部历史打卡和备注及待生效计划将删除、无法恢复、其他习惯不受影响、已有公开分享需单独撤销；未保存备注存在时 MUST 告知草稿会丢弃。取消或关闭确认 MUST 不改变任何数据。

#### Scenario: 删除任一状态的有效习惯
- **WHEN** 用户打开一个有效习惯的“更多操作”，并点击“删除习惯”
- **THEN** 系统显示目标明确的确认弹窗，提供“取消”和“删除”，未确认前不发送删除请求

#### Scenario: 取消有草稿的删除
- **WHEN** 当前习惯有未保存备注，用户取消删除确认
- **THEN** 习惯、全部记录和备注草稿保留原值，弹窗已说明未保存备注的影响

### Requirement: 删除仅作用于受信账户内的目标习惯

系统 MUST 仅依据受信平台上下文确定账户，在一次原子操作中移除目标习惯的全部计划版本及全部日期记录，包括已完成、未完成、调小目标和备注。其他习惯、其他记录、账户 epoch、主题及其他设置 MUST 保持不变，目标置顶引用除外。删除立即生效，无回收站或恢复入口；无效目标或非法参数 MUST 被拒绝。

#### Scenario: 删除包含历史记录与未来计划的习惯
- **WHEN** 用户确认删除一个有历史打卡、备注及明日修改的习惯，云端接受请求
- **THEN** 该习惯及它的全部记录一并移除，今日任务与进度统计不再包含它，其他习惯及其记录保持不变

#### Scenario: 不同账户使用相同习惯标识
- **WHEN** 两个账户拥有同名或相同标识的习惯，其中一个账户执行删除
- **THEN** 仅该受信账户的目标被删除，另一账户数据保持不变

#### Scenario: 客户端伪造身份或目标不存在
- **WHEN** 请求包含客户端身份字段、非法版本或标识，或目标不在受信账户中
- **THEN** 请求被拒绝，不改变该账户或其他账户数据

### Requirement: 并发、重试与确认有效期

系统 MUST 保留既有云端操作幂等、账户版本冲突和账户 epoch 校验。一个已提交删除在结果未知时 MUST 使用原操作重试，不创建新删除来猜测结果；相同操作重放 MUST 不重复执行。确认弹窗期间已确认数据变化、日期变化、账户切换或页面失效 MUST 使旧确认不可执行，用户需重新查看并确认。

#### Scenario: 连续点击和重复确认
- **WHEN** 用户连续点击删除或重复触发确认回调
- **THEN** 同一时刻只出现一次有效确认并提交一次删除，进行中入口不可再次提交

#### Scenario: 另一设备先修改了账户
- **WHEN** 删除请求提交时云端版本已与客户端不一致
- **THEN** 系统返回冲突并更新可核对的数据，不自动删除或覆盖另一设备修改，用户重新确认后才能再次删除

#### Scenario: 旧弹窗跨日、跨账户或跨页面访问
- **WHEN** 用户点击旧弹窗确认时，日期、账户、页面可见性或页面访问版本已变化，或已确认数据已更新
- **THEN** 系统不发送该旧确认的删除请求，不显示成功

#### Scenario: 已执行删除的同一操作重放
- **WHEN** 云端已完成删除但客户端未收到回执，客户端使用原操作标识重试
- **THEN** 云端返回匹配的既有确认及当前快照，不再修改版本或删除任何新建对象

### Requirement: 云端确认与页面恢复

系统 MUST 在合法云端回执或后续核对确认前保留目标草稿及核对入口，不做乐观删除或将目标显示为已删除。成功确认后 SHALL 清除该账户内目标习惯的备注草稿；仍处于原详情访问时返回“我的习惯”并提示“习惯已删除”，栈内已有管理页时退回，否则替换详情进入管理页。断网不可提交；结果未知、服务故障或明确拒绝 MUST 提供相应状态与重试/读取出口，不能将结果未知表述为确定失败或成功。失效页面的迟到回执 MUST 不导航、不弹成功提示或污染新账户界面。

#### Scenario: 删除最后一个习惯
- **WHEN** 云端确认删除当前账户的最后一个习惯
- **THEN** 用户返回“我的习惯”，清单为空且保留“添加习惯”入口，可以创建新的习惯

#### Scenario: 删除失败或结果未知
- **WHEN** 删除请求被拒绝、传输失败或回执无效
- **THEN** 系统不提前清除草稿或显示“习惯已删除”，保留读取或原请求核对入口，断网期间不可继续修改

#### Scenario: 重新进入已删除详情
- **WHEN** 用户重新打开已确认删除的习惯链接
- **THEN** 显示“没有找到这个习惯”和“返回我的习惯”出口，不渲染空白有效详情

#### Scenario: 迟到回执到达其他页面或账户
- **WHEN** 删除已提交后用户离开详情、重新进入详情或切换账户，旧请求才完成
- **THEN** 回执按原账户的请求处理，但不操作当前页面导航、成功提示或新账户草稿

### Requirement: 置顶、提醒及公开分享边界

系统 MUST 在目标被置顶时与习惯删除原子地清除相同账户和 epoch 的该置顶引用，保留其他偏好。提醒 SHALL 根据发送前的有效账户任务计算数量，已删除习惯不计入；没有待做事项时取消尚未发送的提醒。已有公开分享 SHALL 保持现有独立快照及撤销入口，并在删除确认中说明；删除后新建分享预览和统计 MUST 使用已删除后的状态。

#### Scenario: 删除置顶习惯或置顶其他习惯
- **WHEN** 用户删除一个习惯
- **THEN** 如果该目标被置顶则其置顶引用在同一事务中清除，否则保留原置顶；主题、提醒时段与分享索引保持不变

#### Scenario: 删除后处理尚未发送的提醒
- **WHEN** 删除先于提醒发送前最终核对完成
- **THEN** 提醒数量排除目标习惯，没有其他待做任务则取消，其他习惯的有效提醒仍按现有规则处理

#### Scenario: 已有分享和旧分享预览
- **WHEN** 目标习惯删除完成，用户访问已有公开分享或提交删除前未创建的分享预览
- **THEN** 已有分享遵循现有快照、到期和撤销规则，旧预览因源版本变化不可直接创建，新预览不包含已删除习惯
