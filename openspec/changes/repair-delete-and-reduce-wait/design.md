# Design

## Context

见提案的源码观察。本轮先核对部署版本，不能以本地协议支持推断线上已支持。管理页为非 tab 页面 `pages/manage/index`，现有删除使用 `switchTab` 到今日。共享云每个 transport 闭包独立创建 Cloud；已有账户只读事务产生 start/get/commit 三次 SDK 底层请求。客户端回执先在 validateReceipt 验证，随后 acceptSnapshot 再验一次。

## Goals / Non-Goals

Goals：修正删除返回、减少不必要初始化和读事务，压缩提示占屏时间，以请求数和真实 SDK 序列验证改变。

Non-Goals：不做乐观移除/完成，不持久化连接或数据，不压缩/改造账户数据协议，不自动升级运行环境或付费保温，不承诺未经测量的线上毫秒数。

## Decisions

1. 导航查找页面栈中的管理页并 navigateBack；不存在时 redirectTo。导航失败显示管理页出口，所有回调保持原 context/showVersion 隔离。修改既有删除提案与文档中的“今日”返回描述，数据删除契约不变。
2. repository 增加严格的只读账户读取；handler 认证和请求校验后，正常已有账户直接校验并返回。缺失或 cleanupPending 时继续旧事务流程，读取失败不降级为空账户。并发变化仍由写入 expectedRevision 校验；每次读取都访问云数据库。
3. 模块内 WeakMap 按 wx.cloud API 对象分组，按资源方 AppID/环境标识保存初始化 Promise。构造 transport 时不联网；失败只移除同一失败条目，后续可重试。目标白名单在复用前验证。连接对象不包含本项目额外账户缓存；账户数据仍在各会话内隔离。
4. acceptSnapshot 提取已验证快照接收函数；pull 和冲突快照仍校验，成功 write 路径在 validateReceipt 校验后直接接收，不减少任何校验规则。前台窗口使用确认完成时间，避免慢响应后立即再读。
5. 保留事务完整性；减少 server mutate 中与纯 reducer 重复的深拷贝，保留独立 receipts 数组，失败不能原地污染 saved。完成只保留 1200 ms 原生提示，移除底部反馈及其定时器；列表保持用户选择的展开状态，紧凑行提供详情和撤销。
6. 详情、管理清单和进度习惯摘要展示最新已确认计划状态。详情动作直接命名“暂停”“恢复”“归档”“取消归档”，生效时间放在辅助说明中，移除通用修改撤销及预告区块。今天进行中、明日暂停时，“恢复”在目标等字段一致时通过 cancelFuture 恢复该状态，另有目标修改时只用 status active 保留目标修改。尚未生效归档的“取消归档”恢复当前状态，原来暂停的习惯仍保持暂停；已生效归档通过 status active 设置明日进行中。今天任务及历史统计继续使用日期版本，状态展示只在合法云确认后更新。
7. ui.mutate 绑定当前 context/showVersion，在同次可见访问写入期间不重复进行订阅数据投影，合法成功统一刷新一次；失败先接收可信新快照再显示错误。新访问和其他页面订阅不受原写入抑制。首次/回归完成短后缀改为统一“打卡成功”，不为判断首次额外拷贝全部记录。
8. 动作文案统一“打卡”，包括按钮、成功/等待/撤销、统计、说明与外观预览。保留数据库 status 值与协议动作，备注保存、计划保存仍明确其各自操作。

## Risks / Trade-offs

- 只读期间另一设备变化：返回读取时的合法快照，后续写入仍严格 CAS；不增加缓存有效期。
- 共享初始化串目标：使用资源方、环境及 API 对象完整键，覆盖隔离与失败重试测试。
- 草稿与导航迟到：沿用回执和页面访问隔离，补充管理页返回与导航失败用例。
- 真正耗时可能来自网络/云冷启动：本地只证明请求数、计算和交互时长改变，真实响应需单独验收。

## Migration Plan

用户本轮要求修复后在 dev 实施，执行全部本地验证与生成一致性检查。部署需另行明确目标环境与 API 产物，不改环境变量/数据库规则/其他应用。回退本轮源码片段并重新生成即可恢复事务只读和原提示；代码回退无法恢复已删除数据。

## 2026-10-14 Startup Decisions

1. App onLaunch 最先显式准备共享连接；transport 构造仍不联网，准备与业务请求共用相同目标的 Promise。原生 init 在准备调用中立即发出，不排到可选工厂之后。app.js 的外观、监控模块改为工厂调用时加载。准备失败仍由核心读取展示错误，不向默认环境回退。
2. 首个 App onShow 复用 onLaunch 的 dataReady，成功或失败都不追加 pull；后续前台恢复保留 30 秒确认窗口与网络恢复。用户手动重试、重新回到前台仍可发起新读取。
3. 共享初始化与每次纯 pull 分别有 15000 ms 上限；超时结束逻辑请求并释放 busy，已结束的 Promise 不接收迟到值。初始化失败仅删除自己的连接条目。写请求仍保留原 operationId 和待核对语义；SDK 物理请求可能继续，不把超时描述为云端取消。
4. 今日仅在配置启用或已有注入客户端时加载置顶/提醒、监督、照片模块，照片打卡协调器到首次使用时才加载；置顶与提醒开关独立。API 保持存储就绪门控，guard 在真正执行 mutation/purge 时才加载，清理器在 cleanup 时才加载；加载失败继续拒绝或保留清理中，不能移除已存在约定的限制。
5. 在本机控制台记录 shared_init、account_pull、state_accept、startup_read 阶段与毫秒数、OK/FAILED/TIMEOUT。日志不含身份、环境变量、返回数据或用户输入；日志回调异常不影响数据流程。此记录无需账户绑定，不依赖既有运营监控，也不上报共享监控接口。
6. 回滚仅恢复本轮 App、transport/session、今日和 API entry 片段并重新 build:cloud；不迁移或删除数据。正式部署、真机实测、共用 cloudbase_auth 修改及付费预置实例均不在本地授权范围。

连接准备在核心会话完成配置校验后、可选工厂之前执行，无效命名空间不发鉴权。外观工厂加载异常时使用默认主题并继续核心读取；外观恢复不改变已有数据与云端外观记录。

## 2026-10-15 Startup Experience Decisions

以下决策是本轮现行设计，读取等待预算覆盖 2026-10-14 第 3 项的分别 15000 ms 设计。用户已批准本地实施；0.5 秒为页面框架显示目标，实际耗时由独立运行记录和真机验收确认。

1. 今日页面将页面框架与账户内容就绪分开。首次无可信内容时，导航、标题和固定布局先显示，正文使用两张纯形状骨架卡片。骨架不含虚构习惯、数量、进度或完成状态，不触发空账户创建引导；只有合法账户确认后才能显示真实任务或真实空态。
2. 等待文字分级显示：本次可见读取开始后 0—299 ms 不显示文字，达到 300 ms 显示轻提示，达到 3000 ms 显示慢提示。等待定时器绑定页面访问及读取尝试；成功、失败、超时、隐藏、卸载和新访问到来时清除或失效，不让旧提示覆盖新状态。
3. 单次纯读取自逻辑尝试开始建立 8000 ms 截止时间，共享初始化、等待可复用连接、账户 pull 和接收合法结果共同使用剩余时间，不在第二阶段重新获得完整预算。达到截止时间后释放 busy、显示错误和重试出口；底层物理请求可以继续，迟到值必须经过尝试代际检查才能被拒绝。初始化超时或失败只能移除对应连接条目，不能清掉后续已建立的新条目。
4. 写入继续使用原 operationId、账户 epoch、版本冲突和待核对流程；8 秒读取预算不作为写入失败或取消的判据。网络未知保存不清空输入、不提前确认成功。共享鉴权目标、受信身份及账户格式校验保持现状，不增加本机持久快照或离线队列，不拆分云接口。
5. 同一可信账户会话热返回时，立即使用最近合法确认的内存内容并按现有新鲜度规则刷新；读取中或失败时保留这些内容及可理解的状态。无可信内容、会话失效或账户变化时清除旧投影并显示骨架；旧访问和旧会话的响应不得恢复旧内容。
6. 首帧完成后才启动可选外观远端读取和运营监控上报，使用页面首帧回调及访问标识调度并合并重复触发。首帧前仅保留页面显示所需的默认外观和核心读取准备；可选服务加载或请求失败不阻断首帧与核心账户接收。离页前未执行的回调失效，后续有效访问可继续调度。
7. 验证分别记录页面框架、账户读取和可操作数据的就绪时间。假时钟和隔离测试证明顺序、请求数、期限及状态隔离，原生渲染和真机记录证明页面显示与实际时间；任一类结果不替代另一类。回退只撤销本轮客户端片段，不迁移数据、不改云端协议或远端配置。
