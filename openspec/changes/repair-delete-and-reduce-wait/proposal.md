# Proposal

## Why

用户报告删除未完成、删除后需返回“我的习惯”，以及启动和打卡等待过长、完成提示停留过久。本地代码的删除目标仍为今日，底部完成反馈为 5 秒；已有账户 pull 每次执行完整数据库事务，核心与外观分别初始化共享云，成功回执还重复校验整个账户。实际网络与云函数耗时尚未实测，上一轮删除云代码未部署。

## What Changes

- 删除成功返回“我的习惯”：栈内已有该页面时退回，否则替换详情进入管理页；导航失败保留明确出口。
- 对旧服务不支持删除的明确拒绝提供可理解的提示，保留数据和草稿，不伪装成功；只读核对目标云端版本。
- 正常已有账户的 pull 直接读取云账户文档；账户缺失或清理中仍沿用事务创建与清理。打卡、删除及其他写入保持原子事务。
- 同一 wx API、共享资源方和环境复用一次共享云初始化；不同目标隔离，失败清除初始化结果供重试。
- 合法写回执仅执行一次完整状态验证，前台刷新间隔从实际确认时间计算，减少冗余读与本地处理。
- 完成仅保留 1.2 秒原生 toast，移除底部重复反馈；已打卡列表改为紧凑行，保留详情和撤销入口，由用户展开。
- 详情的更多操作统一提供“暂停 / 恢复”和“归档 / 取消归档”，移除通用撤销修改区块；详情、习惯清单和进度中的习惯状态展示最新已确认设置，今日任务和历史仍按日期生效。
- 打卡和撤销期间合并本页面的重复刷新，移除首次/回归提示所需的额外全账户读取；失败仍刷新可信冲突快照，旧访问不接收成功反馈。
- 任务、进度、说明、主题预览和等待提示统一使用“打卡”，底层命令与历史状态值不变。

### Non-Goals

不增加本机持久快照、离线写队列或乐观完成；不改受信身份、账户 epoch、请求幂等、CAS 或删除范围；不改共享认证、云内存/付费配置或其他小程序资源。云端部署、真实测试数据写入、发布和 Git 合并仍分开执行。

### Acceptance Criteria

1. 云确认删除后“我的习惯”不含目标；已有管理页不重复入栈，从其他入口进入也能正确返回；拒绝和未知结果不提前移除或跳转。
2. 已有正常账户 pull 在真实 SDK 合同中只有一次文档读取，无事务启动/提交；缺失、坏文档、读权限失败和清理中正确处理。
3. 主账户和外观调用共享一次初始化；不同环境/资源方不共享，失败可重试，事务写入和身份约束不变。
4. 写入确认仍由原 operationId 的合法云回执决定；慢请求完成后立即前台事件不再触发多余 pull。
5. 完成只有一个 1.2 秒提示；确认前、失败、离页及账户变化不显示成功。已打卡行显示实际目标、提供详情和撤销，长名称及大字体可正常换行。
6. 暂停后显示“已暂停”和“恢复”，归档后显示“已归档”和“取消归档”；只有可信云确认后更新最新状态，恢复和取消归档保留独立目标调整，今天和历史数据不漂移；错误或失效确认不得改计划。
7. 打卡/撤销仍等待唯一云写回执，本页面每次成功只做一次数据投影，失败/冲突与新页面访问保持可恢复；未部署的云端优化如实说明。

## Capabilities

### New Capabilities

- `cloud-response-and-feedback`: 保持云端真实性的读取与操作等待优化、删除管理页出口和短时完成反馈；删除数据契约仍由既有 `allow-delete-habit` 约定。

### Modified Capabilities

无，主规范目录目前无已归档能力。

## Impact

客户端详情、今日、共享 UI、cloud session 和 cloud transport；服务端 handler、CloudBase repository 及对应云生成副本；SDK、共享云、会话、导航和反馈回归。仅现有渐成账户/偏好资源，不新增依赖或集合。
