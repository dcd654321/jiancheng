# Design

## Context

参见 `proposal.md`。现有 `minimum` 是可选、同单位正整数，核心模型已经验证它小于原目标；今日任务模型已有原目标、今日目标、简化与完成状态。数据由云端权威流程和离线队列负责，本次仅调整客户端表单、文案与列表顺序。

## Goals / Non-Goals

**Goals:** 让主表单直接说明双档目标；今日任务在不改变完成语义的前提下展示当前目标和结果；首次创建后的提示与实际执行日期一致。

**Non-Goals:** 不改变核心模型、服务端协议、集合名称、离线队列、日期计算和现有数据；不增加新的 AI、提醒、分享能力。

## Decisions

1. 将 `minimum` 表单块从折叠的更多设置移到平时目标附近，并沿用现有验证与数据字段。备选方案是复制一份设置入口，但双入口容易产生不一致值。
2. 今日任务用已有 `originalTarget`、`minimum`、`target`、`status` 显示“平时／忙时／今天采用”和“原目标完成／小目标完成”。保持先调整当日目标、再完成打卡的两步确认；不改核心状态机。备选方案是一键简化并完成，容易误记。
3. 首次创建后的引导只保留短暂的客户端界面状态；若任务今天可执行，把新任务排到待完成列表前端。今日没有该任务时从已有计划日期/星期规则计算下一执行日，只提示而不造任务。备选方案是新增云端字段记录引导状态，维护成本和迁移风险高。
4. 文案中的“已记录”“待同步”取现有同步状态，不因引导提示而覆盖云端状态反馈。测试覆盖离线队列，避免视觉优化带来错误承诺。

## Risks / Trade-offs

- [小屏上双档信息变密] → 使用紧凑信息层级，原生模拟器检查折行与操作热区；大字号真机仍需用户验收。
- [首次创建提示与云端加载时序冲突] → 仅在创建成功后设置一次性界面标记，今日页在数据可用时消费；加载和错误态不显示虚假空任务。
- [手动简化与预设忙时目标的文案混淆] → 把“预设忙时目标”和“今天采用目标”分别描述；完成状态按实际当日目标判断。

## Migration Plan

只修改 `dev` 客户端代码和测试，无云函数、数据库、集合或用户数据迁移，不部署正式环境。发布前需完成模拟器与真机验收，并由用户决定合并 `main`。回滚可通过本次独立 Git 提交恢复客户端改动，不触及云端历史记录。
