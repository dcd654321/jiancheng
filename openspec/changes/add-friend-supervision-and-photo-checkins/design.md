# Design

## Context

现有客户端发送白名单命令，核心服务端生成并事务保存账户快照。features已有受鉴权旁表事务，原公开分享仅提供脱敏静态快照；一次性提醒具有认领、重复抑制和unknown状态。三个入口当前关闭。动机与范围见proposal.md。

## Goals / Non-Goals

**Goals:** 独立领域模块、核心事务不可绕过的必传校验、按关系投影、可复验的SDK适配、云端唯一持久数据。

**Non-Goals:** 不复用公开快照承载监督内容，不自动迁移旧数据，不把客户端传入身份或mediaId作为认证，不在本轮部署或开放功能。

## Decisions

1. 监督与媒体使用features函数的独立分派与开关，内部新增supervision/media领域和仓库，不依赖公开分享开关。关系保存双方owner hash/epoch、habitId、确认生效时间和规则版本，查询与读取都重新校验双方账户。邀请使用随机标识、48小时有效，有界申请者，确认事务锁定单习惯席位；称呼只是展示数据，不是身份。
2. 完成命令增加可选mediaIds；核心账户事务提供旁表读取/绑定能力。当天必传由关系规则检查，附件须已上传和元数据核实，绑定与账户变更一起提交。回执重放先于副作用。完成与图片检查独立：pending可完成，pass才能外显，审核失败保留完成并提供更换。删除最后一张必传图片通过显式确认完成与撤销同事务；普通撤销释放展示绑定。
3. 媒体申请由服务端分配本项目uploads暂存路径和文件引用。文件实际字节、类型及长度由服务端核验并冻结到客户端不可写的records路径，防止检查后覆写；使用云SDK安全接口的显式consumer appid路由发起异步检查并校验平台结果回调，不能信任客户端mime/size/pass。内容读取先校验本人或有效关系，再换取最多300秒链接，禁止公开读。未绑定24小时后由受信工作器有界清理；账户/习惯删除先使读取失效再清理私有文件与反向关系。
4. 提醒保留原旧协议；新请求增加type=self/supervisor、businessDate、slot、habitIds/relationIds、预览事项和服务端scopeFingerprint。新任务按接收者/epoch/业务日期/type设文档键，并检查相邻业务日期的真实发送日期，保证每实际发送日每类最多一次。两类模板独立，跨午夜检查保留原业务日期。认领和发送都刷新状态，配额失败不误记sent，unknown不重发；结束关系后的列表和重放只保留预约状态，不再返回已失效事项的标题。
5. UI沿用主题和生命周期守卫。新增监督列表/邀请/详情，今日保留普通打卡，必传才打开照片面板；只在确认成功后清空或变更完成。上传请求/完成请求的未知结果沿用原operationId核对，草稿仅当前会话、限定账户与日期。详情不加入完成/撤销，私人note保持原边界。
6. 发布配置集中在server/supervision-config.js，storageReady、supervisionEnabled、mediaEnabled和supervisorRemindersEnabled默认false；后台资格、存储及真机核验记录在部署清单，不重复添加已核验环境变量。启用前须取得对应证据后更新代码配置并构建。关闭入口时storageReady保持true，核心事务守卫及账户清理持续生效。仅保留HABIT_MEDIA_FILE_ID_PREFIX、HABIT_MEDIA_CALLBACK_TOKEN、HABIT_MEDIA_ENCODING_AES_KEY、HABIT_SUPERVISOR_TEMPLATE及HABIT_SUPERVISOR_FIELDS五项平台相关环境变量；图片配置和模板映射缺失或无效时关闭对应服务。媒体定时器名称固定为jiancheng_daka_media_tick，其认证Message使用回调AES密钥为输入、固定用途标识的HMAC-SHA256派生，不能使用回调Token或其他定时器消息代替；更换AES密钥后需同步更新该定时器Message。

## Risks / Trade-offs

- [个人主体可能不具备监督内容类目] → 服务端与客户端分别默认关闭，部署手册要求真实后台资格确认，不因熟人私密推断可发布。
- [异步图片检查耗时] → 完成和照片状态分开，只有检查pass后外显，回调未知保留处理中而非放行。
- [短时链接已签发] → 新读取即时阻断，旧链接最长5分钟失效；已下载/截图无法收回。
- [监督与提醒跨账户、跨日] → 双epoch与计划历史版本、固定北京时间和事务认领，拒绝客户端身份与未授权范围。
- [功能关闭后的已有必传关系] → 核心规则与数据读取保护保留，不删除历史数据；回滚时不得让旧客户端无图绕过约定。

## Migration Plan

本地添加专属资源声明、索引、私有存储与回调/工作器配置说明并生成云副本，不执行云配置。后续分别授权测试云、验证双账户及真机，再经用户试用和资格确认开放正式能力；提交/推送/main合并保持独立授权。回滚先关闭新邀请、图片外显和发送，保留本人记录与绑定元数据；无自动历史迁移或清空。

2026-10-14用户授权代为配置后，进入共享测试环境准备阶段。部署前备份原函数及配置；共享环境必须使用资源方AppID与明确函数路径，DevTools的--project会覆盖--appid，不能用消费方项目推断资源管理归属。CLI错误文本即使退出码为0也视为失败；执行后独立复查函数状态。资源变更只涉及渐成专属函数/集合和限定照片路径，正式环境与公开入口保持关闭。平台后台访问受阻的模板和消息推送由用户接手，不通过其他渠道绕过访问限制。

用户随后确认暂不增加云资源费用。后续准备 SHALL 使用现有测试资源与额度，不升级套餐、不新增付费服务。现有基础私有权限下的服务端文件归属、客户端拒绝改写和短时链接需要实际验证，不能从自定义规则需要付费直接推断所有私有照片方案都需要付费。拟增加有界的临时验证函数`jiancheng_daka_media_probe`，仅针对一张程序生成的70字节测试图，复用可信平台身份且请求30秒/300秒链接；本机验证包已准备，真实部署及运行需确认新增函数和测试文件的具体范围。该验证不改变正式资源、存储权限或发布开关，不替代双账户验收；真实证据满足原私密读取和不可覆写要求后，再确定业务接入改法。验证范围及通过条件见`docs/friend-supervision-no-extra-cost.md`。

用户对上述新增临时函数和测试图选择“暂不新增测试资源”。系统 MUST 保持该验证未执行，不自动部署该包、不创建测试图，也不通过修改现有业务函数执行同样的新资源创建。本机合同检查仅是工具准备证据，不能勾选真实私有访问、短时链接或双账户验收任务；本变更产品范围保留，开放条件不降低。
