# 渐成产品体验与 UI 设计规格

核验日期：2026-10-07。审查基线：`dev` 分支 `1f75d0b`，下文“当前源码”现状描述以该审查基线为准。用户随后授权本地优化，部分设计已在工作区落地，见第11节及本次OpenSpec变更；云端部署、分享启用与发布仍单独验收。配套 `index.html` 是静态设计线框，所有计数均为排版样例，不是当前账户记录或运行截图。

## 1. 产品判断与设计取舍

目标用户暂定为：希望保持阅读、活动、学习、整理等小习惯，但每天可用时间不稳定的人。依据是当前四类模板、平时/忙时双档目标、轻松回来和不计时的记录方式。需要真实用户访谈确认其频率、痛点强度与替代方法。

保留当前的三个有效设计：

- **双档目标**：忙时仍有一个具体可做的选择，帮助用户开始实际行动。保持平时和忙时记录分开统计。
- **轻松回来**：今日休息不算漏做，不显示积分、排名或连续天数惩罚。再次进入时优先看到今天的一件事。
- **先确认、再保存**：模板、AI 建议、共享计划都进入可编辑确认页；分享先预览公开内容；用户决定后才创建。

当前源码已经具备三 Tab、四类模板、紧凑创建表单、两档完成按钮、完成撤销、事实优先的进度、独立主题 token、云端读取恢复与 AI 基础方案。这些应继续完善。源码确认不等于真机、云端写入或目标用户验证。

当前最影响传播闭环的问题是 `share-view` 主按钮用于再次发送，接收者复制计划使用次按钮，邀请和周进展内容没有正常状态下的开始入口；同时 `config/features.js` 中 `enabled`、`publicShares`、`timeline` 均为 `false`。分享是一项已存在源码的待开放能力，不能作为当前可用赛事卖点。

建议本轮以后按此顺序投入：先验证核心云端操作真实可用 → 提升首次理解和记录语义 → 补全结果解释及接收者路径 → 完成视觉统一 → 在合规核验和独立部署验收后开放价值分享。提醒、主题扩展、泛 AI 聊天、奖励拉新均不占用首轮资源。

## 2. 六项目标如何落在产品中

| 目标 | 页面与操作 | 可观察结果 |
|---|---|---|
| 美观 | 今日用统一字号、间距、双档目标块；进度用事实数字与记录列表；分享封面复用同一排版 | 用户能指出主操作，所有页面组件、颜色、圆角一致 |
| 易用 | 首次今日用情境标题、明确可点的模板；创建页首屏只处理名称和两个目标 | 首次用户说出“先做，再记录；忙时可选较小目标”，无需解释找到开始入口 |
| 好用 | 今天完成直接选记录档位；逐字段校验；失败保留输入；已完成中可继续撤销 | 没有把“记下”当计时开始，误记后可以恢复 |
| 想用 | 首屏展示“3分钟整理，忙时1分钟也能留下记录”的具体价值；模板可修改 | 用户能把某个模板映射到自己的生活，并愿意试一个小目标 |
| 愿意回来 | 待做优先、已完成收起、明日安排清楚；回来不补旧账；进度帮助调整以后计划 | 需求再出现时知道从哪接续，并能解释统计对自己有什么用 |
| 容易传播 | 完成一段真实使用后主动分享匿名双档轻计划；接收者首屏复制计划并确认创建 | 分享理由是“这份做法适合你”，接收者首次有价值使用闭环可完成 |

## 3. 两种视觉方向

| | A：薄雾绿·今日行动（推荐） | B：暖纸墨·习惯手账 |
|---|---|---|
| 适合的感受 | 平静、清楚、有余地；关注今天能做的行动 | 私人、可回顾、有记录感；关注一段时间的积累 |
| 主视觉 | 墨绿主按钮、暖白背景、克制的双档色块；18–28px 标题，分组卡片 | 奶油纸底、深墨文字、少量琥珀强调；细线行表、较大的日期与记录数字 |
| 色板 | 主色 `#355E4C`，背景 `#F6F7F2`，表面 `#FFFFFF`，忙时浅色 `#EDF2E3` | 强调 `#9A4D1F`，背景 `#FBF7EF`，表面 `#FFFDF7`，墨色 `#2F302D`，说明 `#65625A` |
| 布局 | 卡片由“名称 → 双档事实 → 记录动作”组成；结果页保留列表 | 日期作视觉锚点，标题下用横线分段，记录呈纵向手账条目 |
| 识别元素 | 一条主色短线配两档目标；现有 Tab 图标继续用 | 日期数字与规则细线；不引入纸纹图片或手写字体 |
| 代价 | 可延续现有 `mist` 与统一 token，页面重排量较小 | 需要更多页结构变动；密集记录可能弱化“今天开始”的立即行动感 |
| 取舍 | 推荐 A 为赛事默认；当前暖纸白主题继续复用结构 | 作为视觉探索，不在本轮以后同时实现第二套布局 |

推荐 A 的原因：当前薄雾绿已经有品牌基础，用户任务以快速确认安排、完成后记录为主。加强行动层级和双档区别，比新增图片、插画和复杂动效更直接。保留当前原生导航和三 Tab，减少微信环境适配成本。

## 4. 推荐方向的设计 token

以下尺寸以 CSS 逻辑像素为单位；375px 宽为线框基准。小程序目前使用 px，可以沿用，不把整套规格机械乘成 rpx。

### 4.1 颜色

| token | 值 | 用途 |
|---|---|---|
| `page` | `#F6F7F2` | 页底，较白色卡片形成稳定分组 |
| `surface` | `#FFFFFF` | 任务、输入、结果、公开预览 |
| `ink` | `#25352D` | 标题、正文、主要数字 |
| `secondary` | `#5F6C63` | 说明；14px 以上，不再降透明度 |
| `primary` | `#355E4C` | 主按钮、选中、少量强调 |
| `onPrimary` | `#FFFFFF` | 主按钮文字 |
| `soft` | `#EEF2EC` | 普通目标底、分段控件、加载占位 |
| `busyBg` / `busyText` | `#EDF2E3` / `#4D6040` | 忙时目标块、忙时完成状态 |
| `line` | `#DBE2D9` | 仅作视觉分组，不能独自承担交互边界 |
| `controlBorder` | `#7A897D` | 输入与可点边界 |
| `success` | `#355E4C` | 记录已确认，与文本同时出现 |
| `warning` / `warningBg` | `#78591F` / `#FAF1D9` | 保存待核对、临时服务受限 |
| `error` / `errorBg` | `#A23C2E` / `#FFF1EC` | 明确校验和读取失败 |

普通文字与背景对比目标 ≥4.5:1；大字与交互边界目标 ≥3:1。已用sRGB公式量测推荐静态色：正文/页底12.00:1、次文/页底5.12:1、白字/主按钮7.35:1、忙时文字/忙时底6.01:1、错误文字/错误底5.91:1、警示文字/警示底5.74:1、控制边界/白底3.68:1。发布前仍需量测实际组合，包括 `paper`、disabled、selected、按压状态；静态色量测不代表组件与原生设备全部已验收。低对比细线允许作装饰，不用于表达唯一状态。

### 4.2 字体与节奏

使用微信系统中文字体，不下载品牌字体。

| 层级 | 大小 / 行高 / 字重 | 示例 |
|---|---|---|
| 首次价值标题 | 28 / 36 / 600 | 忙的时候，也能做一点 |
| 页标题 | 26 / 34 / 600 | 今日、进度 |
| 分组标题 | 18 / 26 / 600 | 每个习惯的记录 |
| 任务名称 | 18 / 26 / 600 | 睡前读一会儿 |
| 正文、按钮、输入 | 16 / 24 / 400–600 | 目标值、记录动作、输入内容 |
| 说明、字段标签、标签 | 14 / 21 / 400–600 | 不会自动计时、原目标记录 |
| 结果数字 | 36 / 44 / 600 | 7 次；不在同屏重复巨型数字 |

两侧 padding 18，窄屏 ≤340 时 16；内容最大宽 560，在宽屏居中。垂直间距只使用 4/8/12/16/24/32。页标题与副标题 6–8，分组间 24，卡片之间 12，卡内 16，说明到操作 12。文本自动换行；任务名称不得单行截断导致无法区分。对同一用途统一尺寸，不每个页面另配一套。

### 4.3 组件

| 组件 | 布局与尺寸 | 关键状态 |
|---|---|---|
| 主按钮 | 满宽，最小 48 高，12 圆角，12×16 padding，16/24/600 | 按压加深；加载保留宽高并写“正在创建…”；禁用仍清楚可读且旁边解释原因 |
| 次按钮 | 同主按钮尺寸，白底、1px controlBorder、ink 文本 | 不仅降低透明度；按压用 soft |
| 文字按钮 | 最小 44×44 触区，14/21；与相邻按钮留 ≥8 | 撤销、返回、修改；危险操作单独分组 |
| 输入 | 最小 48 高，12 圆角，1px controlBorder；值 16px | 焦点 2px primary 内边；错误 2px error 内边＋下面具体说明 |
| 任务卡 | 16 圆角，16 内边；内容区与操作区 12 | 未记录、记录中、已确认、待核对；同一块中展示档位和数量 |
| 目标块 | 平时/忙时并列，gap 8，每格可伸缩；标签14、数量24、单位14 | 长单位或字体放大改为上下排列；不把展示块伪装成可点按钮 |
| 列表行 | 最小 56 高，左右16；标题16，说明14 | 箭头是形状，不用 emoji；整行可点时有明确按压反馈 |
| 提示 | 12×14 内边，12圆角，14/21 | 成功/警示/错误都有文字标题，色盲可区分 |
| 分段控件 | 外框4内边，各项≥44高 | 选中白底＋600字重＋状态可访问标签 |
| 确认弹窗 | 优先微信原生；标题与后果具体 | “取消”与“撤回分享”；不写抽象“确定” |

只有当前真正能执行的操作显示为按钮；未开放能力不放首页营销承诺。loading skeleton 占位高度与最终内容接近；读取过程中不显示0条记录或空数据。

### 4.4 图标、封面与动效

保留 `assets/tabbar/` 当前统一线性图标及图片资产，本地实现与线框均直接引用；原生导航与Tab文字读取同一theme token。若后续需要让图标颜色与强化主色完全一致，可让 `scripts/generate-tab-icons.cjs` 从同一theme token读取后重新生成，不在本轮扩大资产范围。各页使用同规格 chevron 和微信原生 success icon，不混用 emoji、不同线宽的图标与卡通插画。双档目标本身作为品牌识别元素；不新增照片、背景纹理或与行动无关的装饰。

完成卡移动/折叠 160–220ms；loading 脉冲 1.6s 内轻微透明度变化；不改变页面尺寸、不播放音效、不弹出打卡奖章。操作成功先呈现明确文字再动效。跟随微信/设备可用的减少动效设置；无法读取偏好时提供静态降级。

分享封面采用字号清楚的品牌＋通用类别＋两档目标母版（设计母版1000×800，最终导出尺寸与裁切按父报告核验的官方能力执行）。封面只绘制白名单公开字段，不把任务页面截成分享图，不包含私人名称、备注、头像或账户标识。

## 5. 信息架构与流程

三 Tab 保留：“今日”完成当前任务；“进度”解释真实记录并帮助以后调整；“我的”管理、外观、数据与支持。AI、提醒、分享管理放在相关操作后的次入口，均跟随独立能力状态。

建议把首次模板默认值调到更易启动的量级：阅读5/1分钟、轻松走一会儿10/3分钟、复习5/2分钟、整理桌面3/1分钟。审查基线阅读/锻炼/复习是30/10分钟、整理是10/3分钟；小目标已按本次OpenSpec在本地共享模板表落地，仅影响未来新建，不修改已有习惯。适合度仍需用户验证。“最小起点”只作可改默认，不能声称适合所有人或保证养成习惯。

2026-10-10模板默认值更新：阅读、轻松走一会儿、复习为平时30分钟、忙时10分钟，整理桌面为平时15分钟、忙时5分钟。今日卡片、模板确认页和外观预览共用这些值，给准备与进入状态留出时间；用户可修改后创建，已有计划保持原值。上述小分钟数及相关示例保留为早期设计记录。当前配置与本地验证见[默认时长调整记录](../../DEFAULT-HABIT-DURATIONS-20261010.md)。

| 流程 | 当前源码支持的步骤 | 推荐步骤与减少的负担 |
|---|---|---|
| 首次创建 | 今日4模板/自建 → edit紧凑确认 → 创建 → 今日提示 | 同样3个页面/动作阶段；模板增加明确开始文案，edit把两档含义放在同一组，减少猜入口和理解字段，不宣称减少原本已有步骤 |
| 已做忙时目标后记录 | 今日 → 按忙时目标记下 → 云端确认 → 5秒反馈/已完成 | 保持一次记录按钮；统一成“已做忙时1分钟，记下”，首次提示“实际做完再点”；不添加确认弹窗 |
| 只是想把今天安排调小 | 详情 → 只调整今天目标（不记录）→ 云端确认 | 保留详情入口，命名“今天先做小一点”；持续显示“尚未记录”＋“恢复今天原目标”，避免与忙时完成混淆 |
| AI 小目标 | 选方向/分钟 → 本次数据同意 → 生成 → 预览 → 下一步edit → 创建 | 默认即时看基础方案 → 可直接确认；需要更多建议时再主动点“让AI换个建议”并单次同意；预览同时展示动作、两档、来源、下一步；不自动重试 |
| 接收共享轻计划 | share-view → 次按钮按计划试试 → edit → 创建 → 今日 | 接收页第一按钮“用这个计划开始” → edit → 创建 → 今日；减少同屏分享竞争与找按钮负担 |
| 接收邀请/周进展 | share-view展示后通常只剩分享按钮 | 增“开始自己的小目标” → 今日首次模板 → edit → 创建；获得正常开始路径 |

用户第一次“获得有用结果”的定义分两层：创建后立即得到一份可执行的双档安排；真实做完后获得可回看记录。不能要求用户为了试用直接记录未执行动作。用户测试可使用明确的“练习任务”或参与者当天已做的活动，赛事示例记录必须标识演示数据。

## 6. 关键页面设计

### P01 今日·首次

目标：8秒内理解产品用途，找到适合自己的第一件事，不要求注册或先填写长说明。

首屏顺序（375×812示意设备；原生系统和导航高度由微信提供）：

1. 原生导航“渐成”，内容区18px边距。
2. 28/36标题“忙的时候，\n也能做一点”。说明“为习惯准备平时和忙时两个目标。实际做完，再记下这一点。”
3. 分组标题“从一件小事开始”，14px说明“点示例，下一步可修改”。
4. 优先示例卡：整理桌面，平时3分钟/忙时1分钟，明确按钮“从3分钟整理开始”。卡高约180，包括目标和按钮。
5. 其他3个模板采用2列或等高紧凑行，文案“读一会儿”“轻松走一会儿”“复习一小段”；点击直接进入对应紧凑确认页。资源成本低的版本可保留当前4等权模板卡，在卡内增加“开始 →”和独立双档行；是否强调整理交由5人初测决定。
6. “自己设一个”；AI配置已确认时显示“让 AI 帮我定个小目标”＋“先看建议，再确认”。
7. 三 Tab（今日选中）。

主操作：“从3分钟整理开始”作为明确示例入口；其他模板可直接点，不能要求所有人先做整理。标题只在无习惯时出现；有习惯无今日安排使用休息状态，不重复首次营销。

状态：加载显示“正在读取今天的安排”＋卡片占位；真实空显示上述页面；读取失败显示“暂时没能读取记录”＋“检查网络后重新读取”＋“重新读取”，不得显示创建空页；离线不能创建。

### P02 今日·已有安排与轻松回来

目标：立即找到今天待做的一项，并准确记下实际已做的档位。

顺序：今日/日期＋右侧“添加”44高 → “已记1/3，待做2项”16px → 首次创建提示或轻松回来提示（同屏最多一个）→ 待做卡 → 已完成折叠 → 全做完后明日安排。

任务卡：名称18px；计划时间14px次要；两目标事实紧凑呈现“平时目标5分钟”“忙时1分钟”。375px基准时两档完成操作**并排**，每个按钮最小64px高、gap8，用两行确定排版：普通第一行“已做5分钟”（15/22）、第二行“记下”（14/20）；忙时第一行“忙时1分钟”、第二行“已做，记下”。完整可访问名称仍说明实际做完后的记录动作；记录中用同一按钮的进度状态。设计线框目标块44px高、任务卡内容约190px高，使375×812示例视口在简短标题/回归提示下显示2张完整双档任务卡。可用宽度≤340px或微信大字号时改为纵排，按钮最小48高；大字号两行16/24并允许内容自然增长，不以缩字体或截断文案挤入同排。忙时按钮用浅色且文字清楚，不能禁用或写“小失败”。未做时任务卡整体不呈现成功图标。

“做完再记下，不会自动计时”保留在任务列表前。必要时首次创建引导变成“先去做这一点；做完后，选你实际完成的目标记下”。用户理解验证通过后，不把同一说明复制到每张卡。

轻松回来文案“回来就从今天的一点开始。”放第一张待做卡上方；不显示离开天数/逾期；只做一项后消失。无安排“今天没有安排。休息日不算漏做。”＋次按钮“查看习惯安排”。

记录中仅当前动作显示“正在记下…”，禁止第二次写入；同时整页用14px状态“正在保存这次记录”。未知回执用警示“保存结果待核对”＋“重新读取”，不判为失败，不自动再创建记录。旧页面、跨日与账户切换回执不可改变新上下文。

### P03 编辑·双档确认页

目标：明确确认名称、两个可做目标与首次出现日期，输入负担小。

首屏：返回 → 页标题“给习惯准备两种安排” → “目标可改；确认后创建” → 来源（模板/共享/AI）一行 → 名称 → “两种目标”组合。

名称label14/21、输入48高、右侧20字计数。目标组两行：平时目标数值＋单位picker；忙时目标数值＋相同单位。说明“忙的那天，实际做这个小一点的目标也能记录”。忙时可选但建议模板保留；不能为了统一布局强制生成忙时目标。无忙时使用“添加忙时目标（选填）”。

执行频率和开始日期各一条折叠行，默认“每天”“今天开始”；首次安排摘要“首次安排：今天”必须显示，若今天不符合星期/容量则显示准确日期并解释。更多设置里放计划时间，说明“只用于排序，不会发送提醒”。

底栏固定满宽48高按钮“创建这个习惯”；编辑现有习惯时标题“修改明日计划”、按钮“保存明日计划”，底栏上方“修改从明天生效；今天和历史保持原样”。底栏白底，顶部1px line，左右18，上10，下16＋safe-area-inset-bottom。正文bottom padding覆盖底栏高度。

键盘开启：底栏回到文档流，当前字段、字段说明与错误能滚动到键盘上方；不要再叠第二层固定提交栏。返回未保存时只在有实际改动时询问“放弃这次修改？”；“继续编辑”与“放弃”。保存成功后回今日，定位新习惯并有已创建提示。保存被明确拒绝保持全部输入，恢复可重新提交；未知保存保持输入并先核对结果，避免重复习惯。

字段错误文案：名称空“写一个你能认出的习惯名称”；分钟目标空/非法“填1到120的整数”；其他单位目标“填1到999的整数”；忙时≥平时“忙时目标要小于平时目标”；未选天“至少选一天”；错误定位第一字段，提交按钮不代替错误说明。范围依据当前 `core/habits.js` 的 `validatePlan`，实施时从领域校验派生，不在页面复制另一套规则。

### P04 AI·建议预览

目标：减少“定什么、怎么做”的决策负担，并让用户控制数据发送与最终计划。

输入部分保留四方向、分钟preset和自定分钟，执行安排折叠。推荐进入后按明确默认方向与分钟**即时展示基础方案**，标识“基础方案·本机规则”，不请求数据发送；用户可以直接去可编辑确认页。次按钮“让AI换个建议”才展开单次发送同意与生成按钮，简明正文“本次向 DeepSeek 发送方向和可用分钟，生成建议”，下方“会发送哪些信息？”展开实际字段；修改选项后重新同意。来源与预算/服务受限状态如实呈现。即时基础预览与此渐进流程是拟变更行为，需要提案和恢复路径测试；资源不足时先保留当前显式“查看基础方案”按钮，但不强求首次使用走AI。

建议区域：来源14px“AI建议·待你确认”或“基础方案·本机规则”→ 名称20px → 实际动作16px（例如“选一篇短文，安静读完其中一段”）→ 两档目标块 → 执行安排 → 一条理由 → 主按钮“下一步：修改并确认”。脚注“确认保存前，不会创建习惯”。只有1分钟等合法起点时不强行补忙时档。

生成中明确“正在等待 AI，不会自动重复生成”，次按钮“先看基础方案”。失败“暂时没生成建议，选择和时间已保留”＋重试/基础方案；涉及账户失效要先恢复账户再允许生成，不能用UI恢复按钮跳过安全门禁。服务器不可用时仍可预览基础方案；创建仍依赖当前云端可写账户。

### P05 完成结果·今日全做完

目标：确认记录成功、可撤销、知道下一次回来的位置；不强制转到独立庆祝页。

今日中结果块：状态“已记2/2”→ 标题“今天安排的，都记下了”→ 说明“平时目标1项 · 较小目标1项”→ 已完成默认折叠；用户主动打开后逐项显示名称、记录数量、平时目标与撤销。完成卡使用中性事实“本次记录1分钟 · 平时目标5分钟”，不显示“今天已调小”，也不以记录量差异声称用户显式调整过计划。没有来源字段时无法区分主动调小与直接按忙时目标记录；应在行为提案中明确撤销后的目标语义。若要求恢复记录前目标，要在领域层保存来源/前值并验证幂等与跨上下文，不仅换UI文案。

即时完成反馈保留当前5秒自动收起规则：标题“已按忙时1分钟记下”、习惯名称、44px“撤销”。撤销按钮隐藏后，可在今日已完成继续找到“撤销打卡”。反馈放于可见内容底部/原生Tab之上，safe-area按真实微信可用视口量测；不要遮挡最后一个任务、Tab或输入。无Tab详情页则按该页底部区域计算。

明日安排：标题“明天有2项安排”，列表最多3行“阅读 · 5分钟”；时间与排序说明为次要信息。次按钮“查看近7天进度”，之后“管理习惯安排”。分享入口只在已开放并且用户主动查看结果/详情时以次按钮“把这份轻计划给朋友”出现，不弹出分享、不把完成按钮替换成邀请。

误记/重复点击/撤销中都有当前状态；跨日后文案与撤销绑定原日期，不能撤销到今天的新记录；删除/账户切换后旧反馈立即关闭。

### P06 进度·有用解释

目标：用户看懂自己做了什么，再判断以后要不要调整。

首屏：标题“进度”→ 近7天/近28天分段 → 范围10月1日–7日（含今天）→ 事实卡“记下7次”，下行“平时目标5次 · 忙时目标2次”；卡内或紧接卡下显示“共安排10次，含今天；今天还未结束”。

随后最多3个习惯列表：名称16px、记录n/安排m、两个档位；点进详情。再放建议卡：事实＋条件建议，标签“依据记录提供参考”；建议低于3个安排日时不做判断，保持当前规则。需要调整时给“查看习惯安排”，进入管理/详情后由用户选习惯；禁止跨多个习惯一键自动调目标。

逐日记录在下半屏；保留7列时每列必须≥44px，窄于340px（或微信字体放大导致标签拥挤）优先切换逐日列表，或保持一周顺序的水平滑动行，同屏完整呈现日期、状态与可点区。4+3适合执行星期多选，不用于打散一周日期关系。源码现有7列在375、两侧18、gap5下单元宽约44.14px，320宽时约36.86px，必须用真实可用视口和字体验证。不能把50px高度当作44×44触区已达标的证据。

图例“全部完成、部分完成、未记录、无安排”，单元还有“全/部分/未/休”文字，不能只靠颜色。选中日期下面明确记录档位与状态。解释“忙时目标算一次记录，不等于完成平时目标”；“无安排不算漏做”。降低百分比显著度，把安排总数与数量放在语义相关处，避免只见7次不知分母。

空状态：“记下第一次，进展就会出现在这里”＋“回今日看看”或“创建习惯”，根据是否有习惯选主按钮；加载/失败使用数据恢复组件，不能从失败推断0次。

### P07 创建分享·公开内容确认（待开放能力）

目标：分享者知道谁能看见哪些内容，并分享对别人有用的做法。

主要方案为**匿名双档轻计划**；邀请使用为次方案；一周进展为用户主动选择的可表达结果。进入来源带 `kind=plan` 和当前习惯仅作为预填草稿，服务器重新校验可分享字段。此路由便利若当前不支持需独立提案，不能绕过预览和账户校验。

首屏：返回 → “给朋友一份轻计划” → 说明“分享一个做法，朋友可以改成自己的安排” → 选择自己的习惯（只用于本页）→ 公开类别（阅读/锻炼/复习/整理）→ 公开执行日期默认关闭 → 公开预览卡 → 隐私摘要与确认创建。

预览显示通用类别，不显示私人标题。预览例：“读一会儿 / 平时5分钟 / 忙时1分钟 / 日期由朋友自己选”。摘要“公开：类别、两个目标、单位；不含：私人名称、备注、身份”。开关打开日期后实时更新公开字段摘要，旧预览立即失效，必须重新核验。

源码当前有独立 `onPreview` 云端预览；建议保留必要服务器预览：字段变更后按钮“预览公开内容”，取得预览才出现主按钮“确认创建分享”。创建后进入本人查看页，在那里用原生 `open-type=share` “分享给微信好友”；不要承诺一次点击同时完成异步创建和打开微信分享面板。

状态：尚无可分享双档计划“先给一个习惯设置忙时目标”＋“去我的习惯”；读取失败“重新读取”；预览失败保留选项；创建中锁定字段；结果不确定先核对，不能自动重复创建；未开放时入口不营销，可从已有页解释“分享功能尚未开放”。

固定内容与有效期按当前源码90天说明；本人可撤回，提醒“别人已保存的图片或聊天卡片无法收回”。危险撤回在本人操作中，接收者不见这些管理操作。

### P08 接收分享·第一次有价值使用（待开放能力）

目标：接收者理解朋友推荐的做法，先看公开内容，再按自己的情况创建。

首屏轻计划：品牌14px“渐成·朋友分享的轻计划”→ 标题“忙的时候，也留一点给自己”→ 通用类别18px → 两档目标块 → 一条价值说明“有空读5分钟，忙时1分钟也能留下记录”→ **主按钮“用这个计划开始”** → 次级“先看看渐成怎么用” → 有效期/用户自行记录说明。

`mine=false` 时不把分享给好友放成主操作；只有完成自己的真实使用，或明确想转给合适朋友时提供次入口“把这个做法转给朋友”。`mine=true` 时标题“分享已创建”，主按钮“分享给微信好友”，次操作“回到今日”，管理操作放下方。

正常邀请内容主按钮“选一个小目标”；周进展内容主按钮“开始自己的小目标”，提供“先看这周记录”信息块。不能把别人的周记录导入自己的账户。

接收者流程：打开公开快照 → 理解两档做法 → 用这个计划开始 → edit中显示“朋友的轻计划·可修改” → 修改名称/目标/日期 → 明确创建 → 今日出现任务 → 实际做完再记录。朋友的执行日期未公开时采用默认可修改频率，不伪称继承朋友安排。页面继续保持朋友计划与本人记录分离。

公开阅读不索取头像/手机号/昵称。当前微信平台可信账户上下文满足云端写入前提后才能创建；恢复过程中保留本次草稿并说明“正在读取你的云端账户”；失败“暂时不能创建，方案已保留”＋“重新读取”；离线只能阅读当前有效已加载内容，不建立离线队列。

失效/撤回/不存在统一标题“这份分享已不能查看”，解释不透露账户；主按钮“选一个自己的小目标”，可恢复的网络失败另有“重新读取”。从朋友圈单页场景进入时，原生能力受限须明确“进入小程序后再创建”，使用官方允许的完整小程序入口，不能只依赖失败toast；该项需要真机核验。

## 9. 可执行验收

以下均为未来验收标准；未执行的不勾选。

### 9.1 版式与状态

- 在320/375/430逻辑像素宽、微信普通/大字体、iOS/Android分别截核心页；没有横向滚动、文字遮盖、重要标签截断。长名称20字、合法上限目标120分钟/999其他单位、最长合法单位都可读；输入超限值有清楚的字段错误。
- 主次操作触区均≥44×44；推荐提交48高；375宽进度日历实际测44宽以上，320宽降级为逐日列表或一周横滑，不误选邻日。375×812、正常字号且短任务名时首屏2张完整双档卡；大字号或长标题可以纵向增长并滚动，不截断。
- 原生胶囊不被自绘控件遮挡；本文线框的系统栏/胶囊仅示意，不能用来证明实际适配。
- 每个可执行动作测试默认、按压、loading、disabled、成功、明确失败、结果待核对；状态改变不跳宽高，不仅颜色变化。
- 输入焦点/错误、日期选中、平时/忙时记录有文字辅助；量测对比度达设计目标。

### 9.2 核心交互与数据

- 首次从任一模板点到确认页，不写账户；只有明确创建后新增1个习惯。返回/取消不新增，未保存输入有实际修改才提示。
- 创建后今日定位该习惯，用户知道先去做；忙时按钮只记录实际完成的忙时档位。平时、忙时、仅调整今天三种操作的结果分别可核对。
- 连点、长等、前后台切换不能产生重复记录/习惯；跨日、跨账户、页面离开后旧回执不写新页。
- 一次确认记录显示对应档位和数量；5秒提示收起后还能从已完成撤销；撤销成功计数和进度一致。
- 键盘打开时输入/错误能滚到上方，提交bar不覆盖键盘或字段；返回后只保存明确提交的数据。
- 云端超时保留输入，显示待核对；恢复读取后仅显示最高已确认状态，不将失败画成空账户；断网无账户持久离线队列。
- 进度两个周期按真实记录计算，安排总数同屏可见；无安排、不足3个安排日、今天未结束不作人格或执行时段判断。

### 9.3 分享

- 接收轻计划首屏可看目标并找到“用这个计划开始”；邀请/周进展都能在正常状态开始自己的计划。
- 两个不同真实微信账户测试：看公开内容不出现发起者私名/备注/身份；接收者创建不改变发起者记录；确认前接收者账户没有新增。
- 修改公开选项使旧预览失效，服务器预览/创建皆验证白名单字段；发送标题和封面只含白名单字段。
- 本人创建成功之后才能主动使用微信分享；原生分享动作不等于成功发送，没有把取消分享算转化。
- 撤回/到期/缺id/删除/网络失败有可观察恢复或开始入口；链接撤回不能收回已保存图片，界面事前说明。
- 朋友圈单页、好友转发、从微信卡片进入、后台恢复和新用户首次进入分别真机验证；能力未开放时不呈现假的“可分享”结果。

### 9.4 用户测试

首轮5–8名时间不稳定且有具体小习惯意图的用户，包含小程序熟悉与不熟悉者；后续依据结果扩充。测试先不解释双档目标，记录原话。所有指标是方案验收目标或观测字段，不是当前表现。

| 维度 | 任务 | 记录与初始验收门槛 |
|---|---|---|
| 任务理解 | 看首次页8秒，说出用途和下一步 | ≥80%能复述先做再记录、忙时有较小目标；否则重写首屏 |
| 开始与完成 | 自选模板建自己的安排，完成预先声明的练习记录 | 无帮助完成率≥80%，记录页面耗时和犹豫点；分开安排创建与真实行为执行耗时 |
| 双档语义 | “你已经读1分钟，平时目标5，怎么留下记录？” | ≥80%选忙时记录；没人把按钮解释为开始计时；错一次即回查文案/按钮 |
| 错误恢复 | 非法输入、网络失败、误记并撤销 | 能独立找到具体错误、重试/核对/撤销，恢复输入不丢失；逐例报告 |
| 视觉 | 说出最重要内容；评价是否清楚/轻松/可信 | 记录5分量表和理由；不能只问“美不美” |
| 使用意愿 | 放回自己的生活：什么时候下一次会用？ | 记录具体场景、当前替代方式、担忧；“愿意”不当作实际留存 |
| 分享意愿 | 这份做法想到谁？是否自愿试分享？ | 有具体对象与理由；无对象不引导奖励，不把测试员指令算自发分享 |
| 接收理解 | 独立接收者打开卡片并建自己的计划 | 记录打开到理解、确认创建、首次真实记录；检查是否误以为加入群/排行榜 |
