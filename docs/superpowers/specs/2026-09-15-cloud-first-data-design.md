# 渐成习惯打卡：云端主数据设计

状态：用户已确认，尚未实施。日期：2026-09-15。

## 目标

正式版不再让用户选择“本机模式”或“云账户”。微信云数据库保存唯一可信的习惯、计划和打卡记录；本机仅保存最近一次已确认快照、离线操作队列和必要的界面设置。清理缓存或更换手机后，同一微信用户重新打开小程序即可读取云端记录。

第一版继续控制个人开发者的开发与运维成本：不自建账号系统、不使用手机号登录、不轮询、不引入文件存储或第三方数据库，不自动调用AI。云函数通过微信调用上下文取得APPID、OPENID和SOURCE，客户端不得提交或覆盖身份。

## 方案选择

采用“云端主数据＋本机缓存＋离线队列”。打开小程序时读取一次云端快照；用户操作先安全写入本机队列并更新页面，随后自动提交。服务器以账户版本、数据代际和操作ID保证冲突可见、重试幂等。

不采用以下方案：

- 纯云端、无本机缓存：断网时无法查看或打卡，日常工具体验不合格。
- 本机与云端双模式：用户需要理解数据源，容易在换手机、断开连接和导出时选错，正是当前界面混乱的根因。

## 首次使用与身份

首次进入先展示简短的数据说明，明确将习惯名称、计划、日期、完成数量和可选备注保存到微信云开发环境，并提供隐私与删除入口。用户点击“同意并开始使用”后，客户端初始化云能力并调用一次`pull`。不要求头像、昵称、手机号、联系人或位置，也不要求单独注册。

若用户不同意，不创建本机习惯或云端账户，只保留说明页和再次开始入口，避免形成另一套临时本机数据。涉及微信隐私相关接口时，平台隐私保护指引和授权流程必须与实际调用一致。

同一小程序下以服务端APPID与OPENID的SHA-256摘要作为账户键。摘要用于隔离账户，不在客户端显示完整OPENID，也不把它宣传为匿名化数据。

## 启动与缓存流程

应用启动后存在四个明确状态：

1. `needsConsent`：未完成首次数据说明，不读写个人习惯。
2. `loading`：没有可用缓存，正在读取云端；页面显示“正在读取记录”，不闪现假的空状态。
3. `ready`：已有云端确认快照，可正常使用。
4. `offline`：有已确认缓存但本次读取失败；继续显示缓存，离线操作进入队列并标记待同步。

存在已确认缓存时先显示缓存，再在后台读取最新快照。冷启动读取一次；回到前台仅在缓存超过30秒或存在待同步操作时触发一次串行同步。不设置定时轮询，同一时刻只允许一个网络任务。

云端返回未知格式、错误账户或损坏状态时停止写入，不用空状态覆盖本机缓存。没有缓存且云端不可用时展示重试页，不能让用户在未绑定账户的临时状态下创建习惯。

## 写入与离线

打卡、撤销、今日简化、恢复目标和备注沿用现有持久离线队列：先把操作及操作ID写入本机，成功后更新页面，再自动调用云函数。网络失败保留原操作ID并在下次前台、下一次操作或用户点击重试时提交，不重复计数。

新建、长期编辑、暂停、恢复、归档和设置修改继续要求在线确认。这些操作影响未来计划或全局状态，网络失败时留在当前页面并明确显示“尚未保存”，不制造离线成功假象。

服务器继续执行字段白名单、大小上限、7天离线记录窗口、账户版本比较、操作回执和单账户事务。客户端显示“待同步”不等于云端成功；只有收到匹配账户、代际、版本和操作ID的响应才能清除队列。

## 冲突

另一设备推进云端版本时，不自动覆盖或合并本机待同步操作。客户端暂停提交，保存当前队列与远端快照，在“数据同步”页提供：

- 导出当前缓存和待同步操作；
- 重新读取云端；
- 二次确认后舍弃本机待同步操作并采用云端。

第一版不实现逐条合并。日常打卡冲突预期较少，明确保留数据和人工选择比隐式合并更可靠，也更适合个人开发维护。

## 旧开发数据

小程序尚未公开上线，当前本机记录属于开发测试数据。升级到云端主数据时不得自动上传旧`yidian.native.v1`内容。首次切换前保留原存储键，并允许从“备份与恢复”导出；正式页面不再读取该键作为主数据。

第一版不开发通用历史迁移或自动合并：现有协议只允许最近7天离线记录，直接把任意历史状态上传会扩大服务端攻击面和请求体。需要保留的开发测试记录由开发者先导出，再在云端正式流程中重新创建；旧键只能在明确删除本机数据时清理。

## 页面调整

今日页和进度页删除“本机模式”“未云备份”和数据来源入口。主任务页面只展示习惯与进度。

“我的”页删除“开发测试版”和“云连接与同步—开发测试”，调整为：

- 我的习惯：查看与管理；
- 数据同步：显示“已同步”“同步中”“N条待同步”或“同步失败”；
- 备份与恢复：云端缓存备份及旧本机备份导出；
- 导出打卡记录：CSV，可选择是否包含备注；
- 显示设置：首页短句开关；
- 隐私与数据说明；
- 清除全部打卡数据。

“数据同步”页不再提供连接、断开或切换数据源。它只显示账户同步状态、最近同步时间、手动重试、冲突处理和备份入口。用户不需要理解“云账户缓存”“数据来源”或完整账户标识。

## 删除

“清除全部打卡数据”必须在线执行，连续两次确认后调用云端`purge`。只有云端确认成功，客户端才清理旧快照内容、离线队列、恢复副本、本机导出临时文件和旧开发存储键，并保存服务端返回的空状态作为新的已确认缓存。网络失败时不清本机数据，避免出现云端仍有数据但界面声称已删除。

云端为防止旧设备恢复已删除记录，保留不可逆账户摘要、递增代际、更新时间和删除操作回执，不保留习惯内容或备注。隐私说明必须披露这些最小防回传元数据的目的和保留策略。

## 云端启用与成本

客户端仅在以下门槛全部通过后将`config/cloud.js`设为启用：

- 云函数包完整加载；
- 数据库拒绝客户端直接读写；
- 服务端校验APPID、OPENID和允许来源；
- 服务端环境变量与当前AppID一致；
- 一个开发者账户完成`pull → mutate → pull → purge`闭环；
- 第二个微信账户验证数据隔离；
- 云函数依赖风险、日志脱敏和预算告警完成上线决策。

服务端环境变量为`HABIT_APP_ID`、`HABIT_MINIPROGRAM_ONLY=true`和`HABIT_API_ENABLED=true`。启用环境变量及真实云写入是独立的外部状态变更，实施时必须单独记录并在执行前确认目标环境。

第一版沿用单账户单文档及700 KiB应用上限，最多5个活动习惯、100个保留习惯和256个近期回执。无轮询、无图片文件、无推荐内容后台；冷启动一次读取，每个有效修改最多一次提交，失败重试复用操作ID。达到容量上限时拒绝新增并提示导出，不自动删除历史。

## 错误与可见状态

- 初次读取失败且无缓存：显示重试，不进入可编辑空状态。
- 有缓存时断网：继续显示记录，支持可离线的日常操作，并显示待同步数量。
- 在线计划修改失败：保留表单，不提示成功。
- 同步响应丢失：保留同一操作ID，重试由服务端回执去重。
- 数据冲突：停止自动提交，保留两侧证据并让用户选择。
- 本机缓存写入失败：不更新界面、不发网络请求。
- 云端删除失败：不清本机缓存、不提示删除成功。

## 测试与验收

实施必须测试先行，至少覆盖：

- 未同意说明时不初始化云、不创建本机数据；
- 新用户同意后自动连接云端且不出现数据源选择；
- 有缓存时先显示缓存，云端更新不会回滚其间已确认的写入；
- 清理本机缓存后能从同一微信账户恢复；
- 离线打卡自动排队、前台恢复后自动提交且只写一次；
- 旧开发存储不自动上传、不覆盖云端；
- 两设备版本冲突不丢待同步操作；
- 删除必须云端确认后才清缓存；
- 页面不再出现“本机模式”“开发测试版”“使用云账户”等发布禁语；
- 云功能关闭或服务端未启用时安全失败，不接触现有记录。

本地测试、模拟传输和微信编译通过后，再在测试云环境使用无私人内容的测试习惯完成单账户写入/删除，确认习惯、记录和备注为空且仅保留防旧设备回传所需的账户摘要、新代际、更新时间和删除回执；随后进行第二账户隔离和iOS、Android真机验证。正式上线验收要求：清缓存可恢复、断网不丢已排队打卡、页面无开发术语、删除语义真实、云端费用和错误可观察。

## 回滚

实现阶段先创建完整文件检查点。客户端发布开关与服务端开关分开：若联调失败，先关闭客户端联网，再关闭服务端写入；保留云端数据和本机队列，不用空状态覆盖。代码回滚不等于云端数据回滚，任何云端删除都需要另行确认。
