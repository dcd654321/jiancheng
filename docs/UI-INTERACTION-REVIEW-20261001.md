## 1. 已做好的部分与复核边界

### 可以保留

- **配色已经明显收敛。** 薄雾绿使用 `#F7F8F5` 浅底、`#486557` 主色；暖纸白使用 `#FAF8F3` 浅底、`#79604F` 主色。青柠改成浅色忙时标签，今日列表没有整条高饱和青柠按钮。两主题共享布局，不需要再全面换色。
- **创建路径清楚。** 空态提供四个模板和自定义入口；确认页解释“点下面的按钮才会创建”，频率、开始日期有摘要，提交按钮固定在底部。受控创建成功后回到今日，并在新任务附近出现一次指导。
- **核心语义基本正确。** 原目标和忙时目标有明确文字；受控忙时完成后显示今天 2 分钟、原计划 5 分钟；撤销后仍保留今天 2 分钟，可另行恢复原目标。没有把撤销等同于恢复长期计划。
- **进度与恢复有所改善。** 真实进度页显示完成次数、实际安排、原目标/忙时次数；日期格含文字。受控读取失败有“重新读取”，重试后恢复；受控离线已有内容保留，记录按钮禁用。
- 采样记录按钮为 **320×50 CSS px**。两主题选取的 18 个正常文字/控件边界 token 组合均达到对应的 4.5:1 / 3:1 门槛；这不代表全部页面、禁用态和读屏已验收。

“不刺眼、舒服”目前是设计评审判断，尚无真实用户偏好结果。这里建议保留颜色，通过布局和反馈修复继续提高品质。

### 采用当前决策，不拿旧稿误判

现有实施记录明确记载后续调整：模板改为读书/锻炼/复习 **30/10 分钟**、整理 **10/3 分钟**；删除“帮我定个起点”；完成确认后**立即移入已完成并自动展开**。本轮以这些调整核对。旧 A11 的 5/2 默认值、A22 原位保留、A43 助手入口不能继续作为当前失败条件。旧 5/2 计划仍是合法历史/测试状态，并不要求迁移成 30/10。

### R3：按钮看起来能操作，页面实际上忽略；撤销中没有状态

**场景与依据。** 今日 3 个待做任务，第一项忙时记录暂不返回。第一项变灰并显示“正在记录…”，其余任务仍显示正常记录按钮。调用第二项处理器前后，内存 dispatch 调用数均为 1，操作被串行锁忽略。已完成项撤销暂不返回时，`recordingId=review-read`，完成事实保留，但按钮仍为“撤销打卡”，无加载或禁用外观。

依据：[其他按钮仍正常](audits/2026-10-01-ui-interaction-review/32-other-actions-during-record-F.png)、[撤销等待](audits/2026-10-01-ui-interaction-review/33-undo-inflight-F.png)、[调用记录](audits/2026-10-01-ui-interaction-review/inflight-observations.json)。代码：`miniprogram/services/ui.js:60,82`，`miniprogram/pages/today/index.wxml:45,49`，`miniprogram/templates/task.wxml:26–40`。已完成模板没有传入 `recordingId`；模板撤销文案固定。

**影响。** 用户可能以为点不中而反复点击；误操作后无法判断撤销有没有开始。串行保护仍在，本轮未观察到因此产生重复写。

**修改。** 保留串行锁，将页面级 `writeBusy` 和当前操作类型传入待做/完成模板。当前项显示“正在记录…”或“正在撤销…”，其余写按钮禁用；较长等待时提供“正在确认上一项记录”。详情查看、滚动等只读操作仍可用。已确认事实只在合法回执后改变，未知结果沿用既有核对协议。

**验收。** 延迟记录及撤销各一次：①全部写按钮的可点击外观与锁一致；②当前操作文字准确；③连续点其他写按钮不新增意图；④失败保留原事实并可恢复，成功统计一致；⑤两主题均有相同反馈。补行为回归和 F/W 证据。收益是可理解的等待与恢复；代价是共享模板增加少量状态参数。

### R1：重新读取主题后，预览标签与页面配色不一致

**场景与依据。** 当前保存 mist，打开外观页，选 paper；触发实际控制器 `ensureRead(true)`，没有调用保存。读取前 `theme=paper, preview=paper, savedTheme=mist`；读取后 `theme=mist, preview=paper, savedTheme=mist`。卡片仍标“预览中”，按钮仍称“使用暖纸白”，页面底色和选中边界却回到薄雾绿。

![读取前与读取后：预览仍为paper，根theme却回mist](audits/2026-10-01-ui-interaction-review/theme-refresh-comparison.png)

依据：[真实读取观测](audits/2026-10-01-ui-interaction-review/theme-refresh-live.json)。代码：`miniprogram/pages/appearance/index.js:25,37` 自己订阅并应用预览；`miniprogram/services/ui.js:157–165` 另一个订阅写入已保存 `themeSnapshot()`，覆盖预览。

**影响。** 用户无法确认当前看到的究竟是哪套主题；首次读回、重试/冲突后的通知也有同类覆盖路径。

**修改。** 外观页根主题只由 `syncView` 的预览状态决定。共享生命周期提供页面可覆盖的主题更新钩子，或对该页关闭通用根主题覆盖；避免两个订阅争写同一字段。其他页继续跟随已确认主题，缩略图固定各自颜色。

**验收。** 保存 mist 时选 paper，分别在延迟首读结束、强制重读、冲突后读取结束检查：本页根 theme 与 preview 都为 paper；savedTheme 为实际读回值；标签/按钮相符；未点击保存时 setAppearance 为 0；返回后今日仍为已保存主题。收益是预览可信；修改范围小，需回归其他页主题广播。

### R2：旧上下文的未知保存请求没有清掉，阻挡新上下文第一次保存

**场景与依据。** 本地实际客户端/控制器：A/E1 保存 paper 出现模拟回执丢失，冻结请求；切到 B/E2 并成功读到 mist，界面 pending 已为空；B 第一次保存 paper 却返回 `EPOCH_CHANGED`。调用清单只有 E1 的读/写和 E2 的读，**没有发出 B 的新写入**。

依据：[本地实际模块观测 THEME_CONTEXT_PENDING](audits/2026-10-01-ui-interaction-review/code-behavior-probes.json)。代码：`miniprogram/services/appearance-client.js:95` 先检查任何 frozen，`:140` invalidate 不清冻结；`miniprogram/services/appearance.js:56–59` 切 key 只调用该 invalidate。另一个本地观测发现，会话切 key 但未 ensureRead 时，控制器 view 仍暴露 A 的已确认主题；需要一起检查重置时机。

**影响。** 新上下文看起来可保存，第一次点击却报旧账户错误。未观察到跨账户写入或泄露，不能把这个问题描述为数据串号。真实换账户/清理尚未执行。

**修改。** 协调器跟随可信会话的 context/epoch/generation：变化时重置旧预览、已确认主题、读取中状态和过期冻结意图；保存/重放只能处理当前上下文的 frozen。区分“同一上下文未知请求”与“已失效上下文请求”，前者仍须原 payload/operationId 核对。为异步读取/保存增加对应代次校验，旧 finally/catch 不能改新状态。

**验收。** A未知保存→B有效读取→B首次保存应发送 B 自己的合法新请求，不能先报 A 错误；旧回包不得覆盖 B；更换 epoch 后即时回到默认/本上下文已确认值；同上下文重放仍只有一个意图。不用客户端身份绕过。先补 L 回归，再在另行授权的 C 双账户/清理场景验收。收益是可靠恢复；代价为中等状态管理改动。

### R4：自动展开不等于用户看得到完成事实和撤销

**场景与依据。** 3任务从顶部完成读书后，已完成自动展开，但排在剩余任务之后。当前视口只看得到 1/3 与剩余任务；需下滑才能找到“忙时完成／今天2分钟／撤销打卡”。5任务会拉长距离。见[完成后顶部](audits/2026-10-01-ui-interaction-review/14-busy-completed-F-mist.png)、[下滑后的完成项](audits/2026-10-01-ui-interaction-review/15-busy-completed-bottom-F-mist.png)。

**判断。** 事实存在，数据和分组并未丢失；但 Toast 短暂消失后，用户可能难以确认完成了哪一项、按多少记下，也不容易立即纠错。这是界面观察与设计判断，寻找困难程度须 U04 验证。

**修改。** 继续采用“立即移入已完成”。在摘要下方、当前可见区域提供轻量持久反馈，例如“读一会儿 · 已按忙时2分钟记下”，右侧“撤销”。仅在当前日期/账户、本次可见访问中保留；不是另一份任务或统计来源。点击撤销复用既有命令与等待反馈。多次完成可提供“查看已完成（N）”定位入口，不能只覆盖最后一项而令其余无法恢复；不自动滚动打断下一个任务。

**验收。** 1/3/5任务完成后，无需搜索页面即可确认名称和实际目标，立即有明确撤销入口；长期计划不变；跨日/换账户不继承提示；完成行和统计不重复。U04至少5/6独立找到撤销并理解撤销后仍为当日小目标。开发可达性先验，用户成功率须真实测试。收益是纠错容易，代价为新增少量会话展示状态。

### R5：同一卡片同时给两个“2分钟”动作，但一个记录、一个只调整

**场景与依据。** [单任务](audits/2026-10-01-ui-interaction-review/11-one-task-F-mist.png) 同时显示“按5分钟记下”“忙时按2分钟记下”“今天少做一点·2分钟”。第三项只调整目标，语气却接近第二项。源码 `miniprogram/templates/task.wxml:30–32`；有3/5任务时也重复出现。

**修改。** 卡片保留平时/忙时两个记录按钮，把“只调整今天目标”放入详情或轻量更多入口；入口文字明确不记录。已调小状态继续显示“按今天2分钟记下／原计划5分钟／恢复今天原目标”。不删除领域能力，不改变长期计划。

**验收。** 两档主动作能用文字区分；调整入口明确“只调整、不记录”；调整后计数不加、真正完成才加。用 U03 检查5/6能按忙时记录，并让用户说出两种行为的区别。误解是假设，未测前不声称发生率。收益是降低选择负担、压缩列表高度；代价小。

### R6：有错误文案，但输入框没有对应错误边界

**场景与依据。** [忙时30等于平时30](audits/2026-10-01-ui-interaction-review/22-form-error-F-paper.png) 出现具体红字，但输入框仍是正常主题边界。`miniprogram/pages/edit/index.wxml:11,17,30` 仅绑定 focused，未绑定字段错误样式。不能按此前“错误边框已完成”直接验收。

**修改。** 错误字段增加语义 invalid 类，使用 `--color-error` 的2px边界或不占布局的轮廓，配已有具体恢复文字；提交时滚动定位首错，正确输入后及时清除。保留原值，不全表变红。对应标签与输入的读屏关联，在目标基础库/真机上单独验证。

**验收。** 错在哪个字段可直接定位；只标记错误字段；修正即清除；两主题布局高度不跳变；不会提交非法目标；输入、错误和提交在实际键盘上方可达。收益是定位清楚，样式代价小；键盘/读屏需 D。

### R7：主题预览占满首屏，保存按钮露出很少

**场景与依据。** 当前模拟器视口选暖纸白，[初始截图](audits/2026-10-01-ui-interaction-review/07-appearance-preview-LIVE.png) 保存按钮在底部只露出一部分；[下滑截图](audits/2026-10-01-ui-interaction-review/08-appearance-bottom-LIVE.png) 才完整可见。`appearance/index.wxml:25` 为普通文档流按钮，样式没有固定保存栏。

**修改。** 优先复用创建页的固定保存栏，含状态说明和至少48px高按钮，底部加实际安全区；内容区补足栏高和间距，不能盖住第二张预览及错误。或精简缩略图高度使主操作可见，不能靠缩小正文到12px解决。

**验收。** 390px默认字保存按钮完整可达，320px/大字号可滚动内容但按钮不被手势区遮住；使用中/预览中/保存中/失败/待核对都有明确状态；未选择不重复提交；关闭能力不出现可保存假象。收益是下一步容易发现，改造小，需补窄屏 D/W。
