# 删除返回与等待时间修复

2026-10-10，`dev` 本地实现。对应 `repair-delete-and-reduce-wait`，延续 `allow-delete-habit` 的删除数据契约。

## 删除失败的已核实原因

只读下载共享测试环境 `cloud1-d8gopnalv908bb47a` 的 `jiancheng_daka_api` 后，确认远端协议与领域模块均不含 `deleteHabit`。开发者工具和体验版按当前客户端配置使用该环境；用户实际使用入口尚未确认，正式环境本轮未检查。

下载只涉及云函数代码，没有调用业务函数、读取账户数据或删除真实习惯。脱敏源码哈希和待部署包清单见 [repair-cloud.json](audits/2026-10-10-habit-deletion/repair-cloud.json)。客户端遇到旧服务明确拒绝时保留习惯和备注草稿，显示“删除功能暂不可用，请稍后重试。”

## 删除与等待修复

1. 删除只有在合法云回执确认后返回“我的习惯”。页面栈内已有管理页时 `navigateBack` 复用；从其他入口进入详情时 `redirectTo` 管理页。返回失败提供“返回我的习惯”重试出口。取消、拒绝、未知结果和旧账户/页面回调不能提前跳转。
2. 已有正常账户启动读取从 SDK 的事务 start/get/commit 改为一次 get。缺失账户继续事务创建，清理中继续原门禁，读取失败和坏文档不能被当作空账户。主账户、外观及公开分享在相同微信 API 对象、资源方和环境下共用一次共享云初始化；失败后可重试，不跨目标复用。
3. 打卡成功回执完整状态验证由两次减少为一次；慢请求的前台刷新窗口从确认完成时间计算，避免完成后立即多读一次。服务端减少与纯领域 reducer 重复的账户深拷贝。所有写入继续使用事务、版本比较、受信身份、账户代际和原 operationId；确认前按钮保持等待状态。
4. 打卡成功只显示一个 1200 ms 原生 toast，移除今日底部重复反馈及其定时器。离页、跨日或账户变化后的旧回执不弹成功，失败和未知结果不提示成功。

## 暂停、打卡和展开样式

1. 详情根据明天计划显示操作：尚未生效的暂停可“撤销暂停”，已暂停可设置“明日起恢复”。撤销暂停时，若同一天还调整了明天目标，只恢复明日状态，保留目标调整；今天及历史不变。恢复仍受容量和版本约束，旧访问、旧日期确认不能提交。
2. 当前可见访问的打卡、忙时打卡和撤销在云确认后各投影一次，避免订阅刷新与成功回调重复计算和 `setData`。移除首次/回归提示判断所需的额外账户读取；首屏订阅已刷新后不再重复执行启动就绪刷新。其他页面、新访问和冲突后的可信快照继续更新。
3. “今日已打卡”展开后使用一个紧凑清单：每行显示成功图标、名称、本次目标和“撤销打卡”，点击名称可看详情。正常打卡保留用户当前展开选择。名称允许换行，详情和撤销按钮触区至少 44 px，大字体分支将撤销放到下一行。长名称、大字体的微信实际显示仍待验收。
4. 今日、详情、历史状态、进度、帮助和外观预览的打卡动作统一使用“打卡”“打卡成功”“撤销打卡”“未打卡”等文案，平时/忙时目标仍分别展示。

本地证据证明请求数量、计算路径和提示时长变化，未实测网络、云冷启动或真机响应毫秒数。客户端仍以云端为唯一持久账户数据来源。
