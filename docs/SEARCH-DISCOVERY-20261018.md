## 页面与收录

| 路径 | 用途 | 输入 | 输出 |
| --- | --- | --- | --- |
| `pages/discover/index` | 产品介绍与官方模板总览 | 无 | 产品用途、目标说明、使用步骤、四个模板入口 |
| `pages/template/index?key=read` | 阅读打卡计划 | 四个合法模板键之一 | 阅读目标、具体步骤、进入确认页 |
| `pages/template/index?key=walk` | 步行习惯计划 | 同上 | 步行目标与具体步骤 |
| `pages/template/index?key=study` | 学习复习计划 | 同上 | 复习目标与具体步骤 |
| `pages/template/index?key=tidy` | 桌面整理计划 | 同上 | 整理目标与具体步骤 |

介绍页不接受收录参数，模板收录规则只允许 `key` 参数。模板值由页面检查；未知值显示返回总览入口，不回显输入。公开页使用原生内容、确定标题与本地好友分享封面，互相提供 navigator 链接。“我的”在读取失败时仍提供介绍入口。普通品牌分享落到公开介绍页。

模板内容复用 `habit-templates.js` 的目标。点击“使用这个模板”进入现有 `edit?template=...` 确认页；实际创建和打卡仍需账户就绪及用户操作。直接打开公开页不执行账户读取；返回公开页时停止私有内容的网络恢复和使用计时。私人路由、个人分享、监督邀请和照片保持禁止收录，原有身份校验继续执行。

## 来源与转化口径

每次有效前台入口生成一个内存访问标识。冷启动的 onLaunch 与首次 onShow 合并；热重入替换来源。只保留场景值、公开路由或固定今日首页路由、合法模板键和随机访问标识。原始 query、referrerInfo、用户标题、备注和照片不进入归因字段；场景 1129 不计入。

本应用业务 API 的 `trackDiscovery` 接收严格白名单的进入、公开页浏览和模板选择事件，写入既有 `monitor_events`；受信平台身份、账户 epoch 和删除事务栅栏决定是否接受，不创建新集合。共享 monitorApi 和管理端未修改。

| 事件类型 | 判断条件 |
| --- | --- |
| `discovery_entry` | 当前访问入口合法，账户已就绪，且该访问尚未接受同类事件 |
| `discovery_page_view` | 展示合法官方公开内容，按访问、路由与模板去重 |
| `discovery_template_selected` | 用户选择合法模板进入确认流程；不表示创建成功 |
| `habit_created` + `payload.searchSource` | 服务端确认习惯已创建 |
| `checkin_completed` + `payload.searchSource` | 服务端确认一次正常或忙时打卡已完成 |

公开纯浏览不主动建账户。首次访客当前访问的有限浏览事件只在内存中保留，随后进入账户操作时尽力发送；不落本机、不跨进程保留、不构成离线业务队列。纯匿名访问人数使用微信后台口径。遥测失败不影响公开内容、创建或打卡；旧云端未声明 `searchAttributionMetadata` 时不发送新统计 action 或保存字段。

创建、打卡事件保留原事件幂等键和服务端确认条件，并附本次操作固定的来源快照。请求重试不切换来源或重复记成功；账户切换、epoch 改变和删除中的旧请求不得写入新账户。

## 本地汇总

输入：由有权限的运营者导出的 `monitor_events`，JSON 数组或每行一个 JSON 对象的 JSONL。每条事件包含 appId、type、sourceUserId、accountGeneration、occurredAt 和 payload。时间接受 ISO 字符串、毫秒数或 `{ "$date": "ISO时间" }`。导出文件放在 Git 忽略的 `qa/local/`，不提交真实用户事件。

```powershell
node scripts/summarize-discovery.cjs qa/local/monitor-events.jsonl
```

输出只包含汇总计数，不输出用户标识或原始字段：

- `totals`：有归因记录的访问数、进入、浏览、选择、创建、打卡访问数。
- `byChannel`：搜索、搜索中使用过的小程序、好友/群分享、公众号文章及其他入口。
- `byTemplate`：四模板、介绍页与无模板首页访问。
- `orderedConversions`：导出范围内，浏览、选择、创建、打卡服务端记录时间顺序完整的访问数。
- `retention`：按北京时间及账户 epoch 计算次日、第七日回访。起点是导出范围内首次观察到的归因访问，不等于账户注册日；后续使用 app_start 或已归因/成功业务事件判断，尚未达到观察日的样本不计入分母。只有完整导出观察区间时才适合比较回访率。
- `ignoredRows`：未参与来源漏斗的输入行数，包括其他应用、爬虫、无归因字段、非法时间和非法来源；其中合法 app_start 仍可用于回访判断。

计数按受信账户、epoch 与访问标识去重。一个访问产生多个创建或打卡仍只记一个转化访问，模板分组使用该访问最后记录的合法模板；来源反映本次访问，不推断具体习惯来自哪个模板，打卡不代表用户终身首次打卡。缺失事件不补算，网络延迟造成记录顺序不同可能降低 `orderedConversions`，应同时查看各环节计数。此脚本不联网、不写云端，也不代表共享管理端已新增报表。

## 部署顺序与回滚

本次交付为本地代码及构建副本。后续授权部署时，先部署本应用 `jiancheng_daka_api`，验证 capability 与事件写入，再上传客户端并验收。生成脚本会同步本应用其他云函数使用的 protocol 副本，但不要求为此部署未受影响函数。无需新资源、账户数据迁移、清空或共用认证配置修改。

回滚本次客户端与业务 API 改动可停止新增归因写入，原账户状态无需转换。已有统计事件按原账户删除清理机制处理，不自动清理历史事件或旧设备数据。

微信后台是否允许搜索、页面收录状态、名称简介、主体可用搜索能力和实际收录情况单独核验。代码配置与本地模拟器结果不等于真实收录、部署或发布。
