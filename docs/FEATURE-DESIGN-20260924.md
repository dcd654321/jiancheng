# 渐成习惯打卡：多任务、提醒、分享详细设计

日期：2026-09-24　状态：待实施详设　配套：[产品方案](OPTIMIZATION-REMINDER-SHARING-20260924.md) · [增量数据库设计](FEATURE-DATABASE-20260924.md) · [现有主数据设计](DESIGN-DATABASE.md)

## 1. 范围与现状

本详设只覆盖「多个今日任务易操作、一次性聚合提醒、可回看的分享、意见反馈」。不做社群、排行榜、分享积分、自由发布文字／图片、自动每日推送或自建反馈工单。最重要的成功路径是：用户创建 3 项习惯后能逐项快速完成；本人能预览并创建一份公开分享，好友能看、本人能回看及撤回。

当前代码的活动习惯上限为 5，`tasksOn` 按计划时间和 ID 排序；今日页已将已完成项折叠，普通完成与「今天少做一点」是两步。计划时间不会发通知。「我的」已有微信原生反馈按钮。云端主账户集合是 `jiancheng_daka_accounts`，旧测试环境仍启用，共享正式环境客户端开关仍关闭。以下新增行为全是**设计**，并未接入代码或远端资源。

## 2. 今日多任务交互

### 2.1 布局与排序

首屏顺序：同步异常提示（仅有异常时）→ 日期及「待做 N／已做 M」→ 待做卡片 → 已完成折叠 → 添加习惯。引导、短句和回归提示不得把首项任务挤出小屏首屏；最多只展示一条引导。每张卡片显示习惯名、今天按多少做、原目标／忙时目标和完成按钮。完成后仅该卡移入已完成区；屏幕保留当前滚动位置，给短暂撤销入口。

排序键为「置顶匹配优先、已填写的计划时间升序、稳定习惯 ID」。最多置顶一个活动习惯，未安排在今天时不占位。排序在本次页面显示期间固定；打卡造成的待做／已做分区变化除外，不按当前时钟不断重排。云偏好不可用时回退原有时间／ID 顺序，主打卡功能仍可用。

### 2.2 操作合同

| 控件 | 行为 | 数据结果 |
| --- | --- | --- |
| 「完成打卡」 | 声明原目标或已手动调小后的今天目标已做完 | 复用现有 `complete`；离线仍走既有待同步队列 |
| 「按忙时目标打卡」 | 仅当版本有合法 `minimum` 且今天未完成时显示；用户完成忙时动作后点击 | 新的原子 `completeMinimum` 命令，同一步写入 `todayTarget=minimum`、`status=minimum`；不能先把目标改小就算完成 |
| 「今天少做一点」 | 无预设忙时目标时保留自填流程；有预设值但用户想填别的更小值时可从详情操作 | 复用 `simplify`，状态仍为 `pending`，之后另点「完成打卡」 |
| 撤销 | 仅撤销当前习惯当天记录 | 复用 `undo`，其他任务不变 |
| 置顶／取消置顶 | 在详情或长按操作菜单选择，不把复杂管理按钮常驻每张卡 | 在线写用户偏好；失败保持原排序并提示，不能假装已同步 |

`completeMinimum` 进入现有 `RECORD_TYPES` 和 7 日离线补同步规则，服务端从当前生效计划读取 `minimum`，不接受客户端提供任意目标；校验今天有安排、尚未完成、`minimum < target`。同一 `operationId` 重放保持既有幂等。离线快照缺失或跨设备冲突仍按现有同步引擎 fail-closed，不新建第二套打卡队列。

### 2.3 特殊状态

- 0 项：按现有模板创建；有习惯但今天休息，提示「今天没有安排」而非「漏做」。
- 5 项已满：仍可查看和打卡；「添加」解释上限并引导暂停／归档，不提供无效表单。
- 跨日或编辑计划次日生效：显示旧卡操作失败后刷新今天，不把旧日期动作错记到新日期。
- 同步中：显示「待同步」和原有失败／冲突入口；不把它计为云端已确认。引导与完成反馈不遮挡其他卡片。

## 3. 一次性聚合提醒

### 3.1 页面与用语

「我的 → 提醒」提供 3 个预设时段：北京时间 08:00、12:30、20:30；不承诺按每个习惯的计划时间单独发送。计划时间仍只影响今日排序。选时段后，页面预演下一次**有安排**的日期；用户必须点击「提醒我下一次」并在微信授权。状态文字只用「未申请」「已申请，等待发送」「平台已接受发送请求」「已取消」「发送未确认／未发送」。平台接口成功不是阅读回执，不能写「对方已收到」或「每日提醒已开启」。

授权属于用户主动动作；拒绝、不可用或模板缺失时仍可正常打卡，页面保留选择时段但显示真实原因。下一次发送机会用完后，可以在用户再次主动操作时重新申请，不能后台偷偷续订。具体模板和个人主体资格需用本账号核验。[微信订阅消息接口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)；[腾讯云示例与一次性额度说明](https://docs.cloudbase.net/recipes/add-subscribe-message-cloud-function)。

### 3.2 生成与发送

用户授权成功后，认证函数按服务端北京时间计算「今天未来时段或下一个计划日」，最多向前找 7 天；无安排则不建待发记录。一个用户同一天最多一个待发聚合提醒。发送前重新读取账户权威状态，只汇总尚未完成的当天任务数；已全部完成、账户被删除、计划暂停／归档、用户撤回、授权不可用时不发。消息正文只用合规模板允许的短字段，点击进入「今日」，不包含私人备注或多项习惯名。

调度采用 3 个固定时段的定时触发器，而不是每 5 分钟全量扫描；每次只查询该时段到期的待发记录，按批次及预算上限处理，时区要在实际控制台核验。[腾讯云定时触发器](https://docs.cloudbase.net/cloud-function/timer-trigger)。发送流程为「事务认领 → 调平台接口一次 → 写结果」；认领后超时或结果不明标为 `unknown`，不盲目重发以免重复通知。平台接受请求仅表示接口返回成功，真机送达另计验收。

### 3.3 准入闸门

必须先确认本小程序能申请真实匹配习惯场景的模板、授权后可发送、共享云调用中的受信身份、实际时区与费用。任一条件缺失，提醒入口不得展示为可用的后台推送；保留产品内计划时间提示即可。该闸门延续[提醒可行性评估](REMINDER-FEASIBILITY-20260924.md)，不是用数据库设计代替平台许可。

## 4. 分享闭环

### 4.1 内容类型与公开边界

| 类型 | 创建页输入 | 服务端生成的公开快照 | 接收者动作 |
| --- | --- | --- | --- |
| 小程序邀请 `invite` | 从预设封面中选一张 | 产品简介、三种快捷模板入口，无个人数据 | 进入小程序／选模板 |
| 轻计划 `plan` | 选择本人习惯和公开类别（阅读／步行／复习／整理），预览是否显示执行星期 | 服务端读取该习惯当前生效版本的单位、原目标、忙时目标；公开标题取预设类别，绝不取私人名称和备注 | 查看；进入完整小程序后复制为自己的计划并确认 |
| 一周进展 `weekly` | 选一条预设感受文案 | 服务端统计已结束的连续 7 天，公开总计划数、原目标完成数、忙时完成数、预设文案；无逐日记录 | 查看；了解「忙时也能继续」 |

首版不允许用户自填文本或上传图片进入公共快照。计划缺少忙时目标时引导本人先设置；周进展没有真实完成记录时不提供发布。所有预览与最终快照字段一致；客户端传来的统计数、习惯标题和账户身份一律不采信。已发布快照不可编辑；想换内容则新建一份并撤回旧份。

### 4.2 创建、好友、朋友圈与回看

「选择类型 → 预览公开字段 → 创建快照成功 → 分享详情页」。详情页有微信好友分享按钮，好友通过 `shareId` 进入只读页；普通用户没有同意个人数据存储前也能阅读公开内容，只有复制计划时才开始自己的账户流程。分享页从顶部就完整显示公开内容，避免朋友圈单页模式因登录／跳转受限而白屏。朋友圈由用户从该详情页微信菜单主动发布，程序不能自动代发；Android/iOS、低版本及单页模式均需实测。[腾讯云带参分享示例](https://docs.cloudbase.net/recipes/add-share-with-params-miniprogram)。

「我的 → 我的分享」列出本人创建的 `invite/plan/weekly` 快照，可预览、再次分享、撤回或删除。文案固定说明「记录创建过的分享，不记录发给了谁」；系统菜单直接转发但未创建快照的行为不进列表。公开有效期 90 天，过期／撤回／删除时接收者只看到统一的「这份分享已失效」；已发出去的微信卡片本身不能从别人聊天或朋友圈强行收回。

### 4.3 分享能力的安全闸门

现有 `jiancheng_daka_api` 要求受信用户身份和同意，不可把它直接开放为访客接口。新增只读公开函数仅按不可猜测 `shareId` 返回白名单快照；内部仅为校验删除代际读取主账户的 `epoch`，绝不向访客返回私人账户对象、备注或 OpenID。由于朋友圈单页模式可能没有通常登录态，而且本项目正式环境为共享云，必须先在隔离测试里验证**未登录访客能读取公开快照，但不能读任何私人数据或其他应用集合**。若平台条件不成立，朋友圈仅可提供用户手动保存并发布的图片，不宣称小程序内容卡片已可用。[微信朋友圈能力说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/share-timeline.html)。

## 5. 意见反馈

「我的 → 意见与问题反馈」继续用现有 `open-type="feedback"`，不自建反馈集合。帮助文案区分「功能建议」与「故障反馈」，但不承诺在应用内查看处理状态。真机测试打开、提交及开发者后台接收；不可用时显示可复制的联系说明，不静默失败。若将来要求在应用内追踪反馈，再单独设计工单数据、反滥用和回复权限。

## 6. 模块与接口划分

- 现有 `core/habits.js`、`server/protocol.js`、同步引擎：只增 `completeMinimum` 命令与测试；主账户 `state` 结构不为这批 UI 功能改版。
- 新的认证功能入口 `jiancheng_daka_features`：偏好读取／修改、创建／列出／撤回／删除分享、申请／查询／取消提醒。所有私有动作共用**已验证**的受信来源身份解析，按现有 `SHA256(APPID:OPENID)` 派生 owner；客户端携带的 owner、AppID、OpenID 不作认证。共享云 `Cloud` 实例及函数名需要白名单扩展，不回退到旧 `habitApi`。
- 新的只读入口 `jiancheng_daka_public_share`：仅按 `shareId` 返回活跃公开快照与过期状态，未登录朋友圈场景单独做能力验证，禁止查询列表。
- 定时入口 `jiancheng_daka_reminder_tick`：只由平台定时器调用；有独立停发开关和每批／每日上限，不接受小程序客户端发起发送。
- 新页面：`pages/reminder`、`pages/share-create`、`pages/share-view`、`pages/share-list`；保留今日／进度／我的三 Tab。全页有加载、空、无权限、网络失败和过期状态。

各动作请求／返回字段、集合索引、所有权、删除流程见[数据库设计](FEATURE-DATABASE-20260924.md)。新增功能不可继承旧测试环境的正式用户数据，也不可把共享资源方 AppID 当成使用方身份。

## 7. 验收与发布顺序

| 批次 | 自动测试 | 必须补的真实证据 |
| --- | --- | --- |
| A 多任务＋反馈 | 0/1/3/5 项排序、普通／忙时命令、离线重放、跨日、冲突、偏好失败回退；反馈入口结构 | 两种系统、窄屏／大字号的实际点击；反馈在后台可收到；正式云双账号隔离 |
| B 分享 | 快照白名单、本人列表、猜 ID、到期／撤回、重复创建、删除后失效、未登录只读和限流 | 好友与朋友圈真机打开；单页模式；共享环境资源权限；删除后旧链接不可读 |
| C 提醒 | 授权结果、一天一条、已完成不发、取消、重复触发、未知结果不重发、账户删除 | 本账号模板资格、用户真实授权、真机收到消息、时区及账单上限 |

每批先建 OpenSpec 提案并获实施授权，单独提交 `dev`；执行 `npm test`、`npm run check`、`npm run check:cloud` 和严格规范校验。真实云写入、集合权限、触发器和隐私文案变更另列部署清单及回滚边界。文档完成不算功能通过验收，更不算可上线。
