### 3.1 对设计的直接约束

分享完成回调不能作为本方案的测量前提。当前 Page 文档描述的是用户发起转发事件，返回字段没有提供可验证的送达收件人或发送完成回调；wx.showShareMenu 的 success 属于菜单设置接口。**这是依据接口合同做出的工程判断**：可以记录分享意图、实际分享入口访问以及业务完成，不能把关闭分享面板或页面再次 onShow 记成“分享成功”。[Page 官方合同](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html)、[菜单设置接口](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareMenu.html)。

分享入口采用普通、静态的次操作。不给分享按钮加红点、闪动或动态催促，不要求分享后解锁核心功能，不用利益引导朋友圈分享。好友业务互动激励并非一概禁止，但需要明确规则和相应互动条件；渐成当前更适合用模板本身的价值传播，先不投入奖励活动。不要把邀请解锁 AI 次数、积分、红包或排名作为使用门槛。[运营规范 5.1、5.28](https://developers.weixin.qq.com/miniprogram/product/)。

分享卡片默认使用专门封面，展示公开模板名称及两档动作，不自动截取个人习惯、日记、账户资料或健康内容。用户自定义计划和成果若后续支持分享，必须先提供内容预览与选择，并实施内容安全与撤回边界设计。模板 ID、source、统计标识均不得认证用户；保存只依赖受信平台上下文，私有习惯集合不得为传播开放匿名访问。[转发指引](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/share.html)、[运营规范 5.12、5.18](https://developers.weixin.qq.com/miniprogram/product/)。

朋友圈后续若投入，应另做完整的静态内容展示，并用 scene 1154 适配系统顶部、底部操作栏；不要直接复用依赖私有云账户数据的今日打卡页。接收者已经能够阅读模板动作；完整业务通过微信系统入口进入后继续。朋友圈阶段不能为了读取个人计划而开放未登录云权限。[朋友圈官方说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/share-timeline.html)。

## 4. 推荐传播路径

以下属于产品设计建议和待验证假设，并非平台新增能力或已实现功能。

### 4.1 优先复用公开轻计划快照

适合分享的人是采用一个简单计划后，想到也想开始阅读、活动身体或重新接续习惯的朋友的人。分享时机放在习惯详情或自己调整好计划之后；本轮不设计打卡完成后强制出现的营销弹窗。主方案复用已有 `share-create` → `share-view` 公开轻计划快照与预览/撤回协议。当前公开能力仍关闭，先修接收和账户准备路径，再按独立授权部署、启用与验收。

- 入口：习惯详情增加普通次操作“把这个安排分享给朋友”，预填既有 `share-create` 的轻计划种类及习惯；保留公开类别确认、服务端预览和明确创建。不得跳过脱敏预览直接发布。
- 分享卡片标题示例：“平时读 5 分钟，忙时 1 分钟”。现有两档共用同一个 unit，保持分钟单位，不混搭页/段。封面 1000 × 800 像素（5:4），包含两档动作及渐成标识；不展示发送者身份和私有记录。
- 接收页复用 `/pages/share-view/index?id=<公开快照ID>`。公开 ID 仅读取经确认发布的白名单快照，不是账户身份，也不能读取发送者私有记录。本轮实施不要求新增分享路由或公开数据模型。
- 首屏顺序：轻计划标题 → 一句话收益 → 两档动作 → 可修改时间/场景的说明 → 主按钮“用这个计划开始” → 次按钮“分享给微信好友”。本人页主操作仍是发送；接收者页主操作是采用。
- 接收者先看内容；选择采用后准备自己的账户并进入可编辑确认。账户或隐私流程如确为保存所必需，应解释用途并接续同一计划，不索取与习惯保存无关的头像、昵称或手机号。
- 云端明确确认创建后，展示“今天就从这一小步开始”；首次打卡必须是用户自己选择。演示记录和模拟回执不进入传播转化指标。
- 参数缺失、快照撤回/到期/删除：解释当前原因，提供“选一个小目标”；保留用户已编辑输入。不要自动创建计划、披露旧快照或进入无说明的空白表单。
- 热启动打开另一张分享：按最新入口展示新的公开快照，隔离旧异步响应。采用带入账户就绪后的可编辑确认，不覆盖已有习惯；不存在可靠已采用映射时不得猜测重复关系。
- 后续再分享：接收者实际采用并体验后，可主动分享自己确认过的轻计划；先验证有用性，不要求形成多级邀请关系。

分享者获得“给朋友一个容易开始的方法”的表达价值；接收者获得可编辑、可直接执行的动作。增长收益仍是假设，需通过真实接收者测试验证。

低成本备选是直接分享代码包内的公开模板。它可减少快照创建与读取依赖，但无法表达分享者调整后的安排、有效期和撤回，也会形成另一套路径。本轮沿用已有快照；包内模板作为后续预算紧张时的独立取舍选项，不增加新的分享路由作为必需任务。

### 4.2 方案取舍与估算

估算为开发排期判断，前提是复用当前公开快照及编辑/保存能力，未包含独立云端部署、能力启用、真机验收、发布审核和赛事材料制作。

|方案|对应用户价值|估算投入|建议与验证|
|---|---|---|---|
|已有公开轻计划快照分享到好友/群|朋友看到具体动作，修改后采用|约 2–3 个开发人日；复用 share-create/share-view，修主次按钮、账户准备、封面和路径|第一阶段优先；先本地修复，再独立授权部署/启用，最后两账户真机验收|
|包内公开模板分享（备选）|朋友直接从通用小起点开始|约 1–2 人日；减少快照依赖，但需独立产品路径选择|后续降成本选项，不与主方案同时作为必需任务；不表达个人已调整安排或撤回|
|自定义成果摘要分享|表达自己的进展，给同类用户方法启发|约 3–5 人日；另需明确用户选择、内容安全、公开记录范围和撤回策略|第二阶段，先做“哪些内容愿意公开”的用户研究。不要把连续天数设成羞耻或比较机制|
|朋友圈静态内容页|公开展示一种方法|约 2–4 人日；需单页模式、封面/内容和无登录验证|后续投入。先保留完整可读内容，再测有效访问和转入完整服务|
|共同计划/邀请搭子|双方在明确授权下互相支持|约 6–10 人日以上；需成员授权、数据可见性、退出、删除和通知规则|本次参赛优先级较低。只有真实用户需要共同执行时再提案|
|邀请奖励、积分或 AI 次数奖励|增长意图明显，核心习惯收益较弱|除业务开发外还需规则、反滥用、核销与审核|当前不推荐。不能用预计裂变收益抵消未知的体验和运营成本|

统计数据、公开 UGC 或协作变化均需按仓库约定先提 OpenSpec，再取得适用实现授权；云端部署、能力启用及发布分别授权。本文件不执行这些动作。

|分享发起率|触发 onShareAppMessage 的用户数 / 看见适用分享入口的用户数|share_entry_view、share_intent；按钮和菜单分开，同用户/分享种类/当日去重|代表意图，用户可能取消，不能称发送成功率|

|分享入口打开量|有效公开快照的落地访问次数与去重用户数|receiver_open；结合 path/query 与 scene，冷、热启动都覆盖|同一群有多人、二次转发和重开；访问数 / 分享次数可能超过 100%|
|接收者采用率|分享来源中云端确认创建计划的用户数 / 接收页去重用户数|shared_plan_adopt_start、plan_create_confirmed；记录快照种类及内容版本|保存回执必须明确，未知结果不计成功；去重方案须符合既有账户和隐私约束|
|接收者首次打卡成功率|确认创建后有首次云端打卡记录的用户数 / 确认创建用户数|first_checkin_confirmed，观察窗口预先固定为 24 小时或 7 天|说明用户自报打卡记录成功，不等于客观证明习惯已执行|
|后续使用|分享来源采用者第 1、7 天访问/再次打卡人数 / 成熟观察窗口内采用者数|D1、D7 分别报访问与打卡；分轻计划/版本/来源观察|官方全量日留存与分享来源队列留存分开，不能混用|
|后续分享|分享来源采用者随后发起轻计划分享的人数 / 该来源采用者人数|reshare_intent；仍只记录主动发起|不能据此推导已实现的裂变系数|

事件仅保留公开快照的必要统计键、来源、版本、操作状态、必要的用户去重键与时间等最小字段。不得把习惯正文、健康内容、手机号、OpenID、好友/群关系直接写入事件属性或分享 URL。不引入本机离线队列或持久账户绑定。项目后台事件配置、授权/告知、数据保留周期与删除能力均需在实现阶段核验。[事件上报官方合同](https://developers.weixin.qq.com/miniprogram/dev/api/data-analysis/wx.reportEvent.html)、[隐私开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。

第一阶段可只做分享种类/来源级统计。若要识别“一个分享意图是否至少产生一次有效打开”，另提不含身份的短期随机标识方案，明确期限、去重和服务端读取边界；不得把该标识当作身份或访问私有计划的凭证。

### 5.2 接收者打开率必须说明分母

**真实自然传播中，本轮可核验的微信 API 无法提供所有已送达收件人数。**因此不能承诺自动测得“已打开人数 / 已收到卡片人数”的真实接收者打开率，也不能用 onShareAppMessage 次数偷换分母。

可报告两个不同的指标：

1. 自然传播报告“分享入口打开量”和“每次分享意图带来的有效访问量”，并明确其不是收件打开概率。若实现随机意图标识，可报告“至少产生一次有效打开的意图数 / 全部发起意图数”；其中仍含取消意图。
2. 在自愿参加的受控用户测试中，记录人工确认已发送到的单聊收件人数，再测 24 小时内打开人数 / 已确认收到人数。单聊与群聊分开；不知道群成员实际送达数时不计算该组打开率。人工发送由测试参与者自行完成，本轮没有发送任何消息。

首轮可招募 6–8 位符合目标场景的发送者，每人选择一位确有相关需求且同意参加的接收者。报告实际样本、取消、打开、采用、失败原因及观察窗口；不以小样本预测大规模增长。具体招募人数是研究设计建议，未开展测试。
