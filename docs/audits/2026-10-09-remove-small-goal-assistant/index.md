# 小目标助手移除前后验证

当前“小目标助手”只按四方向固定规则预填习惯，预览后仍进入可编辑的习惯表单。现有四模板及常驻忙时目标已经覆盖这些设置，按用户授权移除助手。

## 实际页面观察

移除前“我的”含助手行；阅读基础方案为平时5分钟、忙时2分钟，下一步为确认习惯。见[移除前我的](before-01-mine.png)、[移除前规则预览](before-02-rules.png)和[操作记录](before-observations.json)。

移除后“我的”的习惯管理仅保留我的习惯：

![移除后我的](after-01-mine.png)

| 操作 | 结果 | 页面证据 |
| --- | --- | --- |
| 打开我的 | 无助手行，App不初始化助手服务 | [我的](after-01-mine.png) |
| 今日展开添加 | 四模板与手动入口保留，无助手入口 | [模板选择](after-02-add-templates.png) |
| 点击阅读模板 | 打开可编辑确认，忙时输入框默认可见 | [模板表单](after-03-template-form.png) |
| 空账户点击添加习惯 | 直接打开空名称表单，忙时目标默认可见 | [自定义表单](after-04-custom-form.png) |
| 打开旧助手草稿链接并尝试保存 | 停用提示保持，不创建任何习惯 | [旧链接](after-05-retired-link.png) |

以上为微信开发者工具中的隔离内存场景（F级）。实际tap及路由已检查，创建命令为空，无运行异常，退出后无临时夹具，见[操作记录](after-observations.json)。工具内调用旧链接保存处理函数仅核验拒绝路径，不发送真实业务写入。历史全量审查截图仍保留原状态，本记录提供当前助手移除后的证据。

自定义表单及旧链接页面已独立重开补拍，见[补拍记录](render-recapture-observations.json)。名称、平时目标及忙时目标控件实测高度均为48px，宽度354/248/354px。开发者工具旧链接截图的标题文字未绘制；停用提示、输入控件及拒绝保存已通过页面查询和事件核验，真机呈现尚未验收。
