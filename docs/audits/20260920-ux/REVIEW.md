# 渐成习惯打卡：易用性、视觉布局与健壮性评审

日期：2026-09-20。对象：当前原生微信小程序。方法：按产品设计审查流程，以本轮实际截图为视觉证据，配合源码和纯内存异常复现；不使用旧截图评价当前界面。

## 结论

方向合理，但还不够顺手、精致，异常恢复也有明确缺陷。保留“今日／进度／我的”三Tab、白底深绿、原生组件和云端主数据，优先压缩创建流程、突出核心操作、统一数据管理，并修复重试和草稿问题。

- 易用性：核心功能可找到，但首次创建暴露太多选项，几个数据入口重复，解释偏技术化。
- 美观性：配色、文字和控件有一致性；问题主要是信息权重与密度分配、星期换行、选择器可操作性提示不足，而非缺插图或特效。
- 健壮性：代码已有身份校验、幂等与冲突保护、确认缓存和删除确认机制；本轮仍复现首次失败重试失效、备注草稿被覆盖，确认网络恢复与同步状态通知存在缺口。

不以测试数量或单张成功页面给“上线合格”背书，也不以未经用户测试的主观分数代替结论。

## 需要先修的健壮性问题

以下为当前代码的独立审查结果，没有通过修改真实云数据制造故障。可复现脚本：[robustness-probes.cjs](D:/codex/coding/yidian-miniprogram/docs/audits/20260920-ux/robustness-probes.cjs)，只使用内存账户、存储和传输。

### R1 / 高：首次读取失败后，同步页重试无法恢复

无缓存、已同意、首次读取失败后，同步页显示“重新读取”；按钮调用 session.refresh，而该方法先要求已有engine。网络恢复后点击，实际未发起新请求，仍提示“请先阅读说明并同意连接”。内存复现确认重试的网络调用增量为0；改用已有start路径能成功。

- 代码：[同步页入口](D:/codex/coding/yidian-miniprogram/miniprogram/pages/sync/index.js:25)、[会话refresh](D:/codex/coding/yidian-miniprogram/miniprogram/services/cloud-session.js:160)。
- 改法：统一ensureReady/reload入口，无engine调用start，有engine保留缓存再refresh；按钮处理用户任务，不暴露会话初始化细节。
- 验收：首次请求失败，网络恢复后只点一次重试，不需回首页、清缓存或重复同意；保留已输入草稿。

### R2 / 高：未保存备注会被页面刷新覆盖

详情onNote只修改页面data；refresh无条件用已保存的task.note覆盖它。内存加载实际详情控制器后，输入未保存文字，再执行onHide/onShow，文字变为空。应用回前台或延迟数据刷新也应检查这一风险。

- 代码：[详情刷新](D:/codex/coding/yidian-miniprogram/miniprogram/pages/detail/index.js:22)、[备注输入](D:/codex/coding/yidian-miniprogram/miniprogram/pages/detail/index.js:28)。
- 改法：区分已保存值与dirty草稿；刷新只更新未编辑字段。暂离保留本页草稿，离开详情时提示放弃或保存；保存确认后再清dirty。无需立即新增复杂云草稿系统。
- 验收：输入→切后台/返回/云请求完成，未保存文字仍在；取消放弃不丢文字；保存失败不能假称成功。

### R3 / 高：离线与已同步状态表达不完整

同步页标题只判断conflict/pending，没有判断phase或lastError。有缓存但刷新失败时，实际状态可以同时是ready=true、phase=offline、pending=0；此时标题仍选中“数据已同步”，下方又显示错误。旧记录已保存与当前未能确认最新状态必须分开表达。

首页取得syncText但模板未展示。当天打卡先本地入队、再后台提交；短暂toast消失后，如果上传失败，主任务列表缺持续可见的风险说明。正常状态无需常驻大告警，异常时必须可见。

- 代码：[同步标题](D:/codex/coding/yidian-miniprogram/miniprogram/pages/sync/index.wxml:19)、[首页模板](D:/codex/coding/yidian-miniprogram/miniprogram/pages/today/index.wxml:17)。
- 改法：统一状态模型与通知，区分“已保存到云端／正在同步／离线，显示上次记录／有N条待同步／需要处理冲突”。异常时首页显示窄提示，可进入处理页；不要重新放回“本机模式”或让用户选择数据来源。
- 验收：成功、失败、重试、冲突后所有可见页面状态一致；云端未确认的操作不能暗示已经安全备份。

### R4 / 中高：网络恢复本身没有触发重试

当前session有入队后的提交和onForeground重试，未见onNetworkStatusChange监听或受控的联网恢复调度。内存复现：离线打卡留下1条队列，网络恢复但不触发前台事件时仍为1；调用onForeground后归零。不能把“重回小程序会重试”等同于“停留页面恢复网络就会自动同步”。

- 代码：[提交调度](D:/codex/coding/yidian-miniprogram/miniprogram/services/cloud-session.js:178)、[前台处理](D:/codex/coding/yidian-miniprogram/miniprogram/services/cloud-session.js:191)。
- 改法：注册一次网络恢复监听，合并重复触发，复用单飞提交；冲突和终止性拒绝不自动重试。需要退避和次数上限，不采用高频轮询。
- 验收：断网打卡→不离开页面→恢复网络，队列自动提交且UI同步更新；反复网络抖动不重复记录、不产生请求风暴。

## 分页优化方案

### 今日：打开就知道下一件事

保留日期、完成进度和任务列表。顶部改为紧凑“今日＋日期”，短句降为一行辅助内容；“添加习惯”保持固定可发现位置，避免随完成分组大幅移动。已完成默认显示摘要，允许展开；全部完成时保留轻量反馈，但不把主要空间给重复鼓励语。

任务行保留名称、目标、完成按钮。未设置时间时不必每行写“时间不固定”。“今天简化”可改为“今天少做一点”，并直接显示示例“今天做2分钟，原目标5分钟”，明确只改今天且仍需打卡。不要默认替用户降低目标。

这是二值完成记录，不是自动计时器或数量累计器；页面标签应避免让人误以为会自动计时。当前字段说明已解释“不做数量累计”，可以保留在首次说明或目标帮助中。

### 创建：默认简单，更多设置按需展开

默认只显示名称、每次目标、哪些天做。选填的计划时间、忙时备用目标、明天开始放更多设置；默认每天、今天开始，并在保存前给一句摘要。

星期布局固定七列，窄屏使用简短标签与适当间距，保留足够触控高度；不能只在大屏排得下。目标单位加下拉提示；按钮保持主要颜色。保存失败留在表单，错误靠近具体字段。

代码还存在名称输入maxlength=40、业务校验最多20个Unicode字符的限制不一致：应统一计数与提示，避免输入后直到页面底部保存才报错。数字范围也应就地提示，而不是只说超出范围。

### 进度：先回答“这周做了多少”

保留近7/28天切换。首屏突出完成次数与计划次数，比例作辅助。保留按天查询，但补齐未完成状态的图例，不只靠绿色深浅区分。休息/未开始不等于漏打卡，不能为视觉简化改变统计定义。

顶部口号缩小。选中日期的明细和所有习惯统计分层，避免同一条习惯重复占据首屏。详情历史从有效开始日期显示，或只列最近有安排的记录，再提供展开，不填满创建前的空历史。

### 我的与数据管理：减少入口和术语

我的保留习惯管理、偏好设置、数据与隐私、帮助反馈。数据管理下集中同步状态、CSV导出、备份用途、旧数据迁移与删除，保留能力但减少主列表入口。

跳转行用一致的进入提示；开关维持原生样式。删除放二级页独立危险区域，明确清除哪些云端和本机数据，并继续等待云端确认。没有实际备份文件导入功能时，不以“恢复备份”暗示支持覆盖恢复。

同步时间转为本地“今天14:32”或“几分钟前”，同时可查看完整时间；“确认快照”改为“这台设备保留了最近的记录”。

### 计划助手：AI是增强，不是入口负担

先选择方向与可用时间，直接给出一个小目标。星期/时间预填并可改，“使用这个计划”进入确认，不再次问一遍相同问题。基础建议正常可用时，不在主按钮写“用本机规则建议”。

AI未接入时明确基础建议来源，但不突出开发状态或假称AI。接入后提供“帮我细化”或“调整目标”，不做必经聊天流程；保留真实来源标识、用户确认、限额和降级。

## 视觉与可访问性

保留现有白底、深绿主色、系统字体及线性Tab图标，采用轻分组和稳定对齐。标题、核心指标、普通标签、说明文字分清层级，不是所有页面都用大口号开场，也不为填空白添加插图、渐变和卡片。

当前代码已有不少button、输入label、打卡aria-label，以及44—60px高的操作区域，这是可保留的基础。日历星期为11px、打卡操作说明为12px，在真机与大字号下仍需检查；颜色状态增加文本或符号补充，选择器明确可选。截图不能证明读屏顺序、焦点、对比度合规或缩放可访问性，不宣称符合完整标准。
