配套：[执行规格](AI-OPTIMIZATION-HANDOFF-20260930.md)、[OpenSpec任务](../openspec/changes/refine-journey-and-add-themes/tasks.md)。版本2026-09-30 / v1。**以下是待执行的验收条件，当前均NOT_RUN，不是测试报告。** 原审查中的实际截图、受控渲染、对比度计算仅作为设计依据，不抵扣本清单。

## 1. 如何执行和记录

每条记录：编号、实现版本/工作区差异、执行日期、层级、前置状态、实际操作、实际结果、证据路径、结论、缺陷ID。结果只用PASS / FAIL / BLOCKED / NOT_RUN；SKIP按BLOCKED记录原因，不能计入通过数。

- L：本地行为/合同自动测试，模拟回执须明确标注。只证明覆盖的逻辑。
- W：微信开发者工具实际页面与交互；setData仅验证渲染时标F，不能当真实状态流。
- D：真机，记录设备、OS、微信版本、基础库、字体设置及视口。
- C：授权环境的真实云端/双账户验证，必须明确授权和使用合成测试数据。
- U：目标用户任务测试，不能以AI评审或设计师自己点击代替。

组合如L+W+D表示三个层级分别填结果；一层通过不能把整行勾选完成。当前文档阶段无业务测试运行结果。原项目其他测试记录只作基线，不复制其通过数。

证据建议存 `docs/audits/<实施日期>-journey-themes/`，文件名含 `A编号-theme-尺寸-state`。每项截图配操作/fixture说明；必要时保留短录屏、脱敏请求次数和关键字段断言。不得记录身份明文、令牌、账户绑定配置和原始生产数据。静态概念图不要放进运行截图目录。

## 7. 真实用户任务与成功标准

招募6名接近目标情境的人，至少3名没看过产品。先用当前版本执行任务记录基线，再测试同内容新稿或可交互版本；对熟悉影响采用分组/顺序平衡。不给步骤提示；主持人帮助记作求助，任务不能算独立完成。示例时间是设计验收目标，**不是既有数据，也不是统计显著性结论**。

| 任务 | 给参与者的自然任务 | 成功标准/记录 |
| --- | --- | --- |
| U01 理解/入口 | “看看它能帮你做什么，准备开始一个习惯。” | ≥5/6能用自己话说明习惯记录与忙时较小目标，10秒内找到开始入口；原状先测，时间目标可依据基线调整并记录理由 |
| U02 创建 | “想每天读一会儿，平时5分钟，忙时2分钟，从今天开始。” | ≥5/6无讲解创建正确计划；无错误日期/重复创建；完成时长先测基线，不凭空声称减少X%；记录展开频率、回退、求助 |
| U03 记录 | “今天已经读了2分钟，很忙，请记下来。” | ≥5/6选忙时；无需误按原目标后纠正；能说明已记下的是2分钟而非计时器开始。找按钮5秒为待基线验证目标 |
| U04 误触恢复 | “刚才其实还没做，需要撤销；随后想按原来5分钟做。” | ≥5/6找到撤销并理解今日仍2，再找到恢复原目标；记录是否误以为撤销改了长期计划；数据错误容忍0 |
| U05 再次进入 | “隔几天回来，今天只想做一点。” | ≥5/6在10秒内找到今天任务和较小目标；不误认为必须补齐过去；回归提示不带惩罚感，记录原话 |
| U06 主题与偏好 | “选一个看起来舒服的主题，先看看另一种，然后保留喜欢的。” | ≥5/6找到入口并区分预览/保存/取消；能回今日确认；两主题随机顺序展示，记录刺眼感、清晰度与偏好理由，不预设必须喜欢默认 |
| U07 失败恢复 | “刚才没能读取记录，请继续完成今天任务。” | ≥5/6独立找到重试并继续；不误以为数据已丢；数据未确认时无人误认为操作已成功（出现1例即复查文案） |

关键路径产品目标：至少5/6独立完成U02/U03/U04，0数据误记/越权/重复写；任何P0问题先修再测。样本小，只报告人数、步骤和原话，不宣称转化率或留存率增长。视觉偏好不设“某主题必须赢”的指标；清晰度不能因柔和配色变差。

真实用户未开展时，交付结论写“实现通过已列技术检查，用户易用性待验证”。如需要衡量线上效果，先定义经授权且最少采集的成功事件、分母、时间窗与基线；本变更不擅自加入埋点SDK或上传用户任务内容。
