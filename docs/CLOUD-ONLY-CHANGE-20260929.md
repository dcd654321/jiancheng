# 云端唯一存储整改记录（2026-09-29）

## 范围与原因

根据用户要求，活动小程序不再使用微信设备存储保存账户、习惯、打卡、设置、短句索引或离线操作，也不再生成本机 CSV/JSON 文件。云端是唯一持久数据来源；仅运行内存保留已确认快照、未保存备注草稿和当前未确认操作。

本次仅修改 `dev` 工作区、测试和本地云函数构建产物。测试云 `cloud1-d4gq76oyt363f08a7` 仍由活动客户端配置指向，正式共享云 `product-d2g59zty74d7d1ec1` 未启用；没有部署函数、修改集合/权限/环境变量、写入或清除远端数据，也没有合并 `main`。

## 实现

- `cloud-session` 冷启动直接 `pull`；云端确认前不展示新打卡。响应可能丢失时，仅本次运行会话保存同一操作标识供幂等重试；重启后重新从云端读取。
- 云端读取失败、断网、删除处理中或操作结果未确认时，页面不提供可编辑的旧缓存视图。冲突响应中的新云快照经验证后成为后续依据，本次操作不报成功。
- 删除清理意图已在云端落库时，之后的 `pull` 可继续清理，不依赖上次客户端持有的删除操作标识。
- 移走活动包中的设备存储、账户绑定、离线队列、旧本机备份实现；移除“导出与找回”页及文件导出入口。历史实现仅作为 `tests/legacy` 回归夹具保留，不进入小程序包。
- 历史设备上已存在的旧键和旧导出文件不自动删除、上传或重放。若用户在旧版有未同步记录，必须先审计，不能把新云端数据误当作它的迁移结果。
- `scripts/check.cjs` 增加活动小程序设备持久化 API 静态门禁。

## 部署与回滚边界

云函数 `jiancheng_daka_api` 的新包包含删除恢复改动，部署前需单独确认精确环境和函数。部署应先于新客户端发布；部署后还要用真实测试账号验证拉取、创建、打卡、冲突、断网重启和删除恢复。当前不将此项标为完成。

代码回滚可对本变更在 `dev` 的提交执行普通 `git revert`；不可把 `main` 提前合并或以本地测试结果宣称上线。回滚不会自动清除或还原云端数据；旧设备键保留原样，避免无意删除历史未上传记录。若未来恢复文件导出，需要单独设计用户触发、临时文件清理与隐私边界。
